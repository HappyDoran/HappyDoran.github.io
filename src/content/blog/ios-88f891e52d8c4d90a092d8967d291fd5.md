## 메모리 구조

프로그램이 실행되면 운영체제\(OS\)는 메모리\(RAM\)에 이 프로그램을 위한 공간을 할당합니다\.

그 공간은 Code, Data, Heap, Stack 4가지로 나뉘어져 있습니다\.

![](<../../assets/blog/ios-88f891e52d8c4d90a092d8967d291fd5/image-001.png>)

## 코드\(Code\) 영역

우리가 작성한 소스 코드가 ` 기계어 형태 `로 저장이 됩니다\.

컴파일 타임에 결정되고, 중간에 코드의 형태가 변경되지 않도록 Read\-Only 형태로 저장됩니다\.

> 💡 <strong>기계어</strong>
> 
> 0과 1로 이루어진 컴퓨터가 읽을 수 있는 가장 밑단의 언어

## 데이터\(Data\) 영역

` 전역 변수, static 변수 `가 저장됩니다\. 

프로그램 시작과 동시에 할당되고, 프로그램이 종료되어야 메모리가 해제됩니다\.

실행 도중 변수값이 변경될 수 있으니 Read\-Write로 지정됩니다\.

```swift
struct Korean {
    static var country: String = "Korea"  //static 변수는 데이터 영역에 할당
}

var name : String? //전역 변수는 데이터 영역에 할당
var age: Int? //전역 변수는 데이터 영역에 할당

func fetchData() {
    print("fetchData")
}

```

static은 기본 동작은 lazy입니다\. 프로그램 시작과 동시에 할당되어 메모리가 올라가진 않고, 해당 값에 처음 접근할 때 값이 할당되어 메모리에 올라갈 것 같습니다\.

## 힙\(Heap\) 영역

프로그래머가 할당/해제하는 메모리 영역

프로그래머는 malloc, calloc으로 힙에 메모리를 할당할 수 있으며, 이를 동적 할당이라고 합니다\. 

→ Swift에서는 위 함수들을 통해 직접 할당할 일이 별로 없습니다\. 

사용하고난 후에는 ` 반드시 메모리 해제 `를 해줘야 합니다\. 그렇지 않으면 memory leak\(메모리 누수\)가 발생\.

Code, Data, Stack중 유일하게 런타임 시에 결정되기 때문에 ` 데이터의 크기가 확실하지 않을 때  `사용됩니다\. 

Swift에서는 언제나 어디서나 힙에 할당하고 있습니다\.

클래스 인스턴스, 클로저 같은 ` 참조 타입의 값 `에서 힙에 할당을 합니다\.

→ Swift는 ` ARC ` 를 통해서 힙에 할당된 메모리가 더이상 쓸모 없어지면\(= 더이상 참조되지 않으면\) 자동으로 해제 해줍니다\.

### 힙의 장점

런타임시에 결정되기 때문에 메모리 크기에 대한 제한이 없습니다\.

본질적인 범위가 전역이기 때문에, 프로그램의 모든 함수에서 액세스 할 수 있습니다\.

### 힙의 단점

할당 작업, 해제 작업으로 인한 속도 저하

이중 해제, 해제 후 사용 등의 힙 손상 작업으로 인한 속도 저하

두개 이상의 스레드가 동시에 접근하려고 할 때 Lock이 걸리는 것과 같은 힙 경합으로 인한 속도 저하

메모리를 직접 관리해줘야하는 귀찮음

## 스택\(Stack\) 영역

함수 호출 시 ` 함수의 지역변수, 매개변수, 리턴 값 ` 등등이 저장되고, 함수가 종료되면 저장된 메모리도 해제됩니다\.

→ 프로그램이 자동으로 사용하는 임시 메모리 영역

컴파일 타임에 결정되기 떄문에 무한히 할당할 수 없습니다\.

```swift
func add(a: Int, b: Int) -> Int { //파라미터 a, b는 스택에 할당됨
    let result = a + b //지역변수 result는 스택에 할당됨
    return result
}
```

우리가 아무렇지 않게 함수를 호출하면 OS는 내부적으로 함수 안에 선언된 파라미터, 지역변수 등을 스택에 할당합니다\.

그 후에 add 함수가 종료되는 시점에 스택에 저장된 메모리는 모두 알아서 반환됩니다\.

스택 = LIFO\(last in, first out\) 데이터 구조 = 먼저 생성된 변수가 가장 나중에 해제됨

CPU에 의해 관리되고 최적화 돼서 속도가 매우 빠릅니다\.

### 스택의 장점

CPU가 스택 메모리를 효율적으로 구성하기 때문에 속도가 매우 빠름

메모리를 직접 해제 해주지 않아도 됨

### 스택의 단점

메모리 크기에 대한 제한이 있음

지역 변수만 엑세스 가능

## 힙 vs 스택

### 언제 힙을 쓰고, 언제 스택을 쓰나요?

스택 : 메모리가 한정되어 있기 때문에, 너무 큰 메모리는 할당할 수 없음

힙 : 데이터의 크기를 모르거나 스택에 저장하기엔 큰 데이터의 경우에 할당

#### 스택에 너무 많은 메모리를 할당하게 되면?

스택 오버 플로우 : 스택에 너무 많은 메모리를 할당하게 되어 자신의 스택 영역을 초과한 경우

### 힙과 스택의 메모리 관계

힙과 스택은 같은 메모리 영역을 공유

![](<../../assets/blog/ios-88f891e52d8c4d90a092d8967d291fd5/image-002.png>)

같은 메모리 공간이지만, ` 힙 영역은 낮은 메모리 주소 `부터 할당 받는 것\.  ` 스택 영역은 높은 메모리 주소 `부터 할당 받는 것\.
