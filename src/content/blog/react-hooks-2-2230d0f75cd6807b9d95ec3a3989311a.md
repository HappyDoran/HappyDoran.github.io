## useState

컴포넌트의 **상태\(State\)를 간편하게 생성하고 변경할 수 있도록 하는 도구\.**

```javascript
const [state, setState] = useState(초기값);
```

setState를 사용해서 state를 변경하게 되면 ` 해당 컴포넌트는 다시 랜더링 된다. `

→ 해당 컴포넌트라는 말은, 그 상태를 가지고 있는 컴포넌트 자신과, 그 상태를 직접 사용하는 하위 컴포넌트들을 말한다\.

### useState 예시

```javascript
function Parent() {
  const [count, setCount] = useState(0);

  return (
    <>
      <button onClick={() => setCount(count + 1)}>증가</button>
      <Child value={count} />
      <Unrelated />
    </>
  );
}

function Child({ value }) {
  return <div>{value}</div>;
}

function Unrelated() {
  console.log("Unrelated 컴포넌트 렌더링됨");
  return <div>나는 관련 없어</div>;
}

// setCount로 상태가 변경되면:
// Parent는 리렌더링됨 ✅
// Child는 count를 prop으로 받고 있으므로 같이 리렌더링됨 ✅
// Unrelated는 count랑 아무 상관 없으므로 리렌더링되지 않음 ❌
```

### useState 배열 추가와, 초기값에서의 콜백함수 사용

```javascript
import { SetStateAction, useState } from "react";
import "./styles.css";

const heavyWork = () => {
  console.log("엄청 무거운 작업");
  return ["홍길동", "김민수"];
};

export default function App() {
// 초기값을 가져올 때 무거운 작업을 수행해야 하는 경우, 다음과 같이 콜백함수를 통해 불러오면, 
// 렌더링을 최초에 한번만 실행.
  const [names, setNames] = useState(() => {
    return heavyWork();
  });
  const [input, setInput] = useState("");

  const handleInputChange = (e: {
    target: { value: SetStateAction<string> };
  }) => {
    setInput(e.target.value);
  };

  const handleUpload = () => {
  // state를 변경할 때 새로 변경될 state 값이, 이전의 state값과 연관이 되어 있는 경우라면, 
  // setState의 인자로 새로운 state를 리턴하는 콜백함수를 넣어주면 좋다. 
    setNames((prev) => {
      return [input, ...prev];
    });
  };

  return (
    <div className="App">
      <input type="text" value={input} onChange={handleInputChange} />
      <button onClick={handleUpload}>업로드</button>
      {names.map((name, idx) => {
        return <p key={idx}>{name}</p>;
      })}
    </div>
  );
}

```

## useEffect

어떤 컴포넌트가 Mount 되었을 때, Update 되었을 때, unMount 되었을 때 **특정 작업을 처리할 코드를 수행하고 싶을 경우 사용하는 도구**

```javascript
useEffect(()=>{
	원하는 작업
},[dependency array]);
```

useEffect는 인자로 콜백함수를 받는다\.

> 💡 **콜백함수란?**
> 다른 함수의 인자로 전달된 함수

### useEffect 예시

```javascript
import { SetStateAction, useEffect, useState } from "react";
import "./styles.css";

export default function App() {
  const [count, setCount] = useState(1);
  const [name, setName] = useState("");

  const handleCountUpdate = () => {
    setCount(count + 1);
  };

  const handleInputChange = (e: {
    target: { value: SetStateAction<string> };
  }) => {
    setName(e.target.value);
  };

  useEffect(() => {
    console.log("렌더링 될 떄마다 매번 실행되는 코드");
  });

  useEffect(() => {
    console.log("count 값이 바뀔 때만 실행되는 코드");
  }, [count]);

  useEffect(() => {
    console.log("첫 렌더링시에만 실행되는 코드");
  }, []);

  return (
    <div className="App">
      <button onClick={handleCountUpdate}>카운트 증가</button>
      <span>count: {count}</span>
      <input type="text" value={name} onChange={handleInputChange} />
      <span>{name}</span>
    </div>
  );
}
```

### useEffect Cleanup

cleanup이란 컴포넌트가 unMount 될 때 실행되는 동작을 useEffect 내부의 return에 추가하는 것\.

```javascript
// App.tsx
import { SetStateAction, useEffect, useState } from "react";
import Timer from "./components/Timer";
import "./styles.css";

export default function App() {
  const [showTimer, setShowTimer] = useState(false);

  return (
    <div className="App">
      {showTimer && <Timer />}
      <button
        onClick={() => {
          setShowTimer(!showTimer);
        }}
      >
        Toggle Timer
      </button>
    </div>
  );
}
```

```javascript
// components/Timer.tsx
import { useEffect } from "react";

export default function Timer() {
  useEffect(() => {
    const timer = setInterval(() => {
      console.log("타이머 돌아가는 중...");
    }, 1000);

		// 다음과 같이 return 내부에 콜백 함수를 넣어주면 unmount시에 해당 코드가 실행된다.
    return () => {
      clearInterval(timer);
      console.log("타이머가 종료되었습니다.");
    };
  }, []);
  return (
    <div>
      <span>타이머를 시작합니다. 콘솔을 보세요.</span>
    </div>
  );
}
```

## useRef

함수형 컴포넌트에서 useRef를 부르면 ref 오브젝트를 반환해준다\.

```javascript
const ref = useRef(value);
// ref 오브젝트는 { current: value }로 생겼다.
```

우리가 인자로 넣어준 초기값은 ref안의 current에 저장이 된다\.

ref 오브젝트는 수정이 가능하기 때문에, 언제든 우리가 원하는 값으로 바꿔줄 수 있다\.

반환된 ref는 컴포넌트의 전 생애주기를 통해 유지된다\.

→ 컴포넌트가 unMount 되기 전까지는 값을 그대로 유지할 수 있다는 것이다\.

### useRef의 쓰임

#### 저장 공간

ref는 state와 비슷하게 저장 공간으로 사용\. 
→ 단 state 변수 변경시 발생하는 **리렌더링이 ref에서는 발생되지 않고, 변수들의 값이 유지**됨\.

또한 state가 변경되어 리렌더링이 발생해도 ref 내부의 변수는 유지됨\.

#### DOM 요소 접근

예시로 input 요소를 클릭하지 않아도 자동적으로 focus 될 수 있게 해주는 작업 가능\.

### 저장공간으로써의 ref \- state와 ref의 차이

```javascript
import { useRef, useState } from "react";
import "./styles.css";

export default function App() {
  const [count, setCount] = useState(0);
  const countRef = useRef(0);

  const increaseCountState = () => {
    setCount(count + 1);
  };

  // ref는 상태가 변화돼도 렌더링이 되지 않는다.
  // 이를 통해 엄청 자주 바뀌는 값을 저장해야할 경우, 
  // ref에 저장을 하면 성능에 좋다.
  const increaseCountRef = () => {
    console.log(countRef.current);
    countRef.current = countRef.current + 1;
  };

  return (
    <div className="App">
      <p>State = {count}</p>
      <p>Ref = {countRef.current}</p>
      <button onClick={increaseCountState}>state 증가</button>
      <button onClick={increaseCountRef}>ref 증가</button>
    </div>
  );
}

```

다음과 같은 코드에서 값이 바뀌게 되면, State는 값이 바뀜에 따라 렌더링이 발생한다\. 하지만 Ref는 값이 바뀌어도 렌더링이 일어나지 않는다\. 

### 렌더링이 발생할 때의 ref \- 일반 변수와 ref의 차이

```javascript
import { useRef, useState } from "react";
import "./styles.css";

export default function App() {
  const [renderer, setRenderer] = useState(0);
  const countRef = useRef(0);
  let countVar = 0;

  const doRendering = () => {
    setRenderer(renderer + 1);
  };

  const increaseRef = () => {
    countRef.current = countRef.current + 1;
    console.log("ref", countRef.current);
  };

  const increaseVar = () => {
    countVar = countVar + 1;
    console.log("var", countVar);
  };

  const printResults = () => {
    console.log(`ref: ${countRef.current}, var: ${countVar}`);
  };

  return (
    <div className="App">
      <p>Ref = {countRef.current}</p>
      <p>Var = {countVar}</p>
      <button onClick={doRendering}>렌더러</button>
      <button onClick={increaseRef}>ref 증가</button>
      <button onClick={increaseVar}>var 증가</button>
      <button onClick={printResults}>Ref, Var 값 출력</button>
    </div>
  );
}
```

다음과 같이 값이 바뀌고, 렌더링이 발생할 경우 일반 변수의 경우에는 렌더링이 일어나면서 다시 값이 0으로 초기화가 된다\. 하지만 Ref의 경우에는 렌더링이 발생해도 이전의 값이 계속 유지 된다\.\(unMount 되지 않는 이상\)

### 렌더링을 발생시키지 않는 ref

```javascript
import { useEffect, useRef, useState } from "react";
import "./styles.css";

export default function App() {
  const [count, setCount] = useState(1);
  const renderCount = useRef(1);

  useEffect(() => {
    renderCount.current = renderCount.current + 1;
    console.log("렌더링 수", renderCount.current);
  });

  return (
    <div className="App">
      <p>Count: {count}</p>
      <button
        onClick={() => {
          setCount(count + 1);
        }}
      >
        올려
      </button>
    </div>
  );
}
```

결론적으로 useRef는 변화는 감지하지만 그 변화가 렌더링 발생시키면 안되는 값을 다룰 때 편리하다\.

### DOM 요소로의 접근

```javascript
import React, { useEffect, useRef, useState } from "react";
import "./styles.css";

export default function App() {
  const inputRef = useRef(null);

  const login = () => {
    alert(`환영합니다 ${inputRef.current.value}`);
    inputRef.current.focus();
  };

  useEffect(() => {
    // inputRef.current.focus();
  }, []);
  return (
    <div>
      <input ref={inputRef} type="text" placeholder="useName" />
      <button onClick={login}>로그인</button>
    </div>
  );
}
```

다음과 같이 작성할 경우에, useRef를 사용해서 쉽게 DOM 요소에 접근할 수 있다\.

## useContext\+ContextAPI

프로젝트에서 사용하는 데이터 중에 전역적으로 사용되어야 하는 데이터\(Theme, Language, UserData\) 들을 여러 컴포넌트들끼리 쉽게 공유할 수 있는 방법을 제공하는 도구\.

기존의 props를 전달해주는 방식처럼 props drilling을 해준다면 굉장히 귀찮고 복잡해진다\.

![](<../../assets/blog/react-hooks-2-2230d0f75cd6807b9d95ec3a3989311a/image-001.png>)

따라서 contextAPI와 useContext를 사용해서 전역적으로 관리할 수 있다\.

> 💡 **context와 props의 차이점은? **
> 
> 
> context는 데이터를 전역적으로 뿌려준다는 측면에서 좋다\. 하지만, context를 사용하게 되면 컴포넌트를 재사용하기 어려워질 수 있다\.
> 
> → Prop drilling을 피하기 위한 목적으로 context를 사용할거라면, Component Composition을 사용하는게 좋다\.

### useContext를 이용한 테마 설정

```javascript
// /Context/ThemeContext.tsx
import { createContext } from "react";

export interface ThemeContextType {
  isDark: boolean;
  setIsDark: React.Dispatch<React.SetStateAction<boolean>>;
}

// 다음과 같이 테마를 전역적으로 관리하기 위한 Context를 생성
export const ThemeContext = createContext<ThemeContextType | null>(null);
```

```javascript
// App.tsx
import React, { useState } from "react";
import "./styles.css";
import { ThemeContext } from "./context/ThemeContext";
import Page from "./components/Page";

export default function App() {
  const [isDark, setIsDark] = useState(false);
  return (
    <ThemeContext.Provider value={{ isDark, setIsDark }}>
      <Page />
    </ThemeContext.Provider>
  );
}

```

```javascript
// /Components/Contents.tsx
import React, { useContext } from "react";
import { ThemeContext } from "../context/ThemeContext";

export default function Contents() {
	// 전역적으로 선언된 Context를 가져와서 사용
  const theme = useContext(ThemeContext);
  if (!theme) return null;

  return <div>{theme.isDark ? "Dark Mode" : "Light Mode"}</div>;
}
```

## useMemo

컴포넌트의 성능을 최적화 하기위한 대표적인 도구\.

![](<../../assets/blog/react-hooks-2-2230d0f75cd6807b9d95ec3a3989311a/image-002.png>)

Memo는 Memoization을 뜻함으로써, 동일한 값을 리턴하는 함수를 반복적으로 사용해야 한다면 맨 처음 값을 계산할 때 해당 값을 메모리에 저장해서 필요할 때마다 또 다시 계산하지 않고 메모리에서 꺼내서 재사용하는 기법을 말한다\. 

→ 자주 필요한 값을 맨 처음 계산을 할 때 캐싱을 해두고, 그 값을 필요할때마다 캐시에서 꺼내서 사용한다는 것

→ 궁극적으로 값을 재사용 하기 위해서 메모리에 저장을 하는 기법을 말함\.

![](<../../assets/blog/react-hooks-2-2230d0f75cd6807b9d95ec3a3989311a/image-003.png>)

함수형 컴포넌트는 말 그래도 호출되는 컴포넌트다\. 따라서 랜더링이 될 경우에 함수를 호출하는데 이 때 모든 변수가 초기화 되면서 calculate 함수도 다시 호출된다\. 이는 매우 불필요하다\.

### useMemo 예시

![](<../../assets/blog/react-hooks-2-2230d0f75cd6807b9d95ec3a3989311a/image-004.png>)

useMemo 안에는 메모이제이션 할 리턴값을 던져주는 콜백 함수, 배열안에는 이 useMemo를 실행할 트리거인 의존성 배열이 들어간다\. 

### 생각이 많이 들어간 메소드를 다룰때 사용하는 useMemo

```javascript
import { useMemo, useState } from "react";
import "./styles.css";

const hardCalculate = (number: number) => {
  console.log("어려운 계산");
  for (let i = 0; i < 9999999; i++) {} //생각하는 시간
  return number + 10000;
};

const easyCalculate = (number: number) => {
  console.log("쉬운 계산");
  return number + 1;
};

export default function App() {
  const [hardNumber, setHardNumber] = useState(1);
  const [easyNumber, setEasyNumber] = useState(1);

  const hardSum = hardCalculate(hardNumber);
  const easySum = easyCalculate(easyNumber);

  return (
    <div className="App">
      <h3>어려운 계산기</h3>
      <input
        type="number"
        value={hardNumber}
        onChange={(e) => {
          setHardNumber(parseInt(e.target.value));
        }}
      />
      <span> + 10000 = {hardSum}</span>

      <h3>쉬운 계산기</h3>
      <input
        type="number"
        value={easyNumber}
        onChange={(e) => {
          setEasyNumber(parseInt(e.target.value));
        }}
      />
      <span> + 1 = {easySum}</span>
    </div>
  );
}

```

다음과 같은 컴포넌트에서 hardCalculate의 경우에는 많은 시간이 걸리기 때문에 딜레이가 발생한다\.
문제는 이 함수형 컴포넌트 내부의 모든 동작이 딜레이가 발생한다\.\(리랜더링이 되면서 hardCalculate가 다시 실행됨\)

```javascript
const hardSum = useMemo(() => {
    return hardCalculate(hardNumber);
  }, [hardNumber]);
```

다음과 같이 hardSum을 useMemo로 선언해주고, 의존성 배열에 hardNumber가 바뀔때만 이 함수를 실행한다 해주면, 다른 메소드나 컴포넌트에 영향을 끼치지 않고, 이전에 했던 복잡한 계산을 저장하여 사용하게 된다\.

### 원시 타입과 객체 타입에서의 useMemo 활용

```javascript
import { useEffect, useMemo, useState } from "react";
import "./styles.css";

export default function App() {
  const [number, setNumber] = useState(0);
  const [isKorea, setIsKorea] = useState(true);

  const location = isKorea ? "한국" : "외국";

  useEffect(() => {
    console.log("useEffect 실행");
  }, [location]);

  
  return (
    <div className="App">
      <h2>하루에 몇끼 먹어요?</h2>
      <input
        type="number"
        value={number}
        onChange={(e) => {
          setNumber(e.target.value);
        }}
      />
      <hr />
      <h2>어느 나라에 있어요?</h2>
      <p>나라 : {location}</p>
      <button
        onClick={() => {
          setIsKorea(!isKorea);
        }}
      >
        비행기 타자
      </button>
    </div>
  );
}

```

다음과 같은 코드가 있다 했을 때, location의 값이 바뀔 때마다 useEffect가 실행이 된다\.

하지만 만약에, 우리가 의존성으로 전달해준 location이 string과 같은 원시 타입이 아닌, 객체 타입이라면 어떻게 될까? 

```javascript
import { useEffect, useMemo, useState } from "react";
import "./styles.css";

export default function App() {
  const [number, setNumber] = useState(0);
  const [isKorea, setIsKorea] = useState(true);

  const location = { country: isKorea ? "한국" : "외국" };

  useEffect(() => {
    console.log("useEffect 실행");
  }, [location]);

  return (
    <div className="App">
      <h2>하루에 몇끼 먹어요?</h2>
      <input
        type="number"
        value={number}
        onChange={(e) => {
          setNumber(e.target.value);
        }}
      />
      <hr />
      <h2>어느 나라에 있어요?</h2>
      <p>나라 : {location.country}</p>
      <button
        onClick={() => {
          setIsKorea(!isKorea);
        }}
      >
        비행기 타자
      </button>
    </div>
  );
}
```

location이 다음과 같이 바뀐다고 했을 때, 분명히 location을 의존성 배열에 추가해줬음에도 하루에 몇끼 먹어요를 수정해줘도 useEffect가 실행되는 모습이 보인다\. 

#### 원시 타입과 객체 타입

![](<../../assets/blog/react-hooks-2-2230d0f75cd6807b9d95ec3a3989311a/image-005.png>)

![](<../../assets/blog/react-hooks-2-2230d0f75cd6807b9d95ec3a3989311a/image-006.png>)

기존의 location처럼 string타입 즉, 원시 타입일 경우에는 다음과 같이 공간에 들어가게 된다\. 하지만 객체 타입의 경우에는 location이라는 주소값을 배부 받게 되어 이 주소값에 대한 공간에 값이 들어가게 된다\. 

그래서 객체타입으로 선언된 location은 리렌더링 될 때마다 새로운 메모리 주소를 가진 객체로 평가되기 때문에 useEffect가 전혀 다른 객체라고 판단하고 매번 실행되는 것이다\. 

#### useMemo 사용법

```javascript
const location = useMemo(() => {
  return { country: isKorea ? "한국" : "외국" };
}, [isKorea]);
```

useMemo를 사용해서 isKorea가 바뀌지 않는 한 같은 location 객체를 재사용하게 설정한다면, 메모리 주소가 유지되기 때문에 number가 바뀔때는 useEffect가 실행되지 않게 된다\. 

## useCallback

useMemo와 마찬가지로 메모이제이션 하는건 똑같지만, useCallback은 콜백함수 그 자체를 메모리에 저장한다\.

> 💡 **useMemo와 useCallback의 차이점**
> 
> ```javascript
> useMemo(()=>{
> 	return value; // value를 메모리에 저장
> },[item]);
> 
> useCallback(()=>{
> 	return value; // callback 함수 그 자체를 메모리에 저장
> },[]);
> ```

### useCallback의 예시

```javascript
const calculate = useCallback((num) => {
	return num+1;
},[item])
// calculate라는 변수는 메모이제이션 된 함수를 갖게 되고,
// item이 변경되지 않는 이상 초기화 되지 않는다.
```

### 객체로서의 useCallback

```javascript
import { useCallback, useEffect, useState } from "react";
import "./styles.css";

export default function App() {
  const [number, setNumber] = useState(0);

  const someFunction = () => {
    console.log(`someFunc: number: ${number}`);
    return;
  };

  useEffect(() => {
    console.log("some Function이 변경되었습니다");
  }, [someFunction]);

  return (
    <div className="App">
      <input
        type="number"
        value={number}
        onChange={(e) => setNumber(e.target.value)}
      />
      <br />
      <button onClick={someFunction}>Call someFunc</button>
    </div>
  );
}

```

useEffect의 경우 someFunction이 바뀔 때만 실행이 되도록 의존성 배열에 추가해놓았는데, number 값이 바뀔 경우에도 계속 호출이 되는 모습이 보인다\. 

useMemo와 마찬가지로 someFunction은 객체 타입이기 때문에, 리렌더링 될 때마다 새로운 메모리 주소를 가진 객체로 평가되기 때문에 useEffect가 전혀 다른 객체라고 판단하고 매번 실행되는 것이다\. 

```javascript
import { useCallback, useEffect, useState } from "react";
import "./styles.css";

export default function App() {
  const [number, setNumber] = useState(0);

  const someFunction = useCallback(() => {
    console.log(`someFunc: number: ${number}`);
    return;
  }, [number]);

  useEffect(() => {
    console.log("some Function이 변경되었습니다");
  }, [someFunction]);

  return (
    <div className="App">
      <input
        type="number"
        value={number}
        onChange={(e) => setNumber(e.target.value)}
      />
      <br />
      <button onClick={someFunction}>Call someFunc</button>
    </div>
  );
}
```

이렇게 해버린다면 이제 useCallback 내부의 콜백 함수가 메모이제이션 되기 때문에, 리렌더링이 된다면 이미 가지고 있는 someFunction의 주소를 가지고 와서 재사용 한다\.

### useCallback을 이용한 컴포넌트 스타일 

```javascript
// App.tsx
import { useCallback, useEffect, useState } from "react";
import Box from "./components/Box";
import "./styles.css";

export default function App() {
  const [size, setSize] = useState(100);
  const [isDark, setIsDark] = useState(false);

      <input
        type="number"
        value={size}

      />
      <button
        onClick={() => {
          setIsDark(!isDark);
        }}
      >
        change Theme
      </button>
      <Box createBoxStyle={createBoxStyle} />
    </div>
  );
}
```

```javascript
// components/Box.tsx

import { useEffect, useState } from "react";

export default function Box({ createBoxStyle }) {
  const [style, setStyle] = useState({});

  useEffect(() => {
    console.log("박스 키우기");

```

위 코드에서는 박스의 크기를 바꾸게 되면 useEffect가 실행이 되며, 박스의 크기가 바뀌고, 콘솔이 찍힌다\. 하지만 테마를 바꾸었을 때도 useEffect가 실행이 되며, 박스를 다시 그린다\. 

따라서 createBoxStyle을 useCallback으로 감싸주어서 사이즈가 바뀌었을 때만 되도록 하면 된다\.

      height: `${size}px`,
    };

## useReducer

여러개의 하위값을 포함하는 복잡한 state를 다룰 때 사용하는 도구

### Reducer, Dispatch, Action

철수가 은행에 방문해서 10000원을 출금해달라고 요구하면 철수의 계좌에서 10000이 빠져나갔다고 기록된다\.

→ 이때 철수의 계좌 내역을 업데이트 하는건 철수 본인이 아닌 은행이 하는 일

철수는 거래내역\(State\)을 업데이트 할 것\(Action\)을 요구\(Dispatch\)하고 은행\(Reducer\)은 계좌 내역을 업데이트를 행함\. 

```javascript
Dispatch(Action) => Reducer(State, Action)
```

### useReducer 예시

```javascript
import { useReducer, useState } from "react";
import "./styles.css";

// dispatch - state 업데이트를 위한 요구
// reducer - state를 업데이트 하는 역할 (은행)
// action - 요구의 내용
const reducer = (state, action) => {
  console.log(state, action);
  switch (action.type) {
    case "deposit":
      return state + action.payload;
    default:
      return state - action.payload;
  }
};

export default function App() {
  const [number, setNumber] = useState(0);

  // useReducer는 배열을 반환. 첫번째는 state, 두번째는 usereducer가 만들어준 dispatch
  // 인자로는 reducer, money의 초기값
  const [money, dispatch] = useReducer(reducer, 0);
  return (
    <div className="App">
      <h2>useReducer 은행에 오신것을 환영합니다</h2>
      <p>잔고: {money}원</p>
      <input
        type="number"
        value={number}
        onChange={(e) => setNumber(parseInt(e.target.value))}
        step="1000"
      />
      <button
        onClick={() => {
          dispatch({ type: "deposit", payload: number });
        }}
      >
        예금
      </button>
      <button
        onClick={() => {
          dispatch({ payload: number });
        }}
      >
        출금
      </button>
    </div>
  );
}

```

### 복잡한 state를 reducer로 다루기 

```javascript
import { useReducer, useState } from "react";
import Student from "./components/Student";
import "./styles.css";

const reducer = (state, action) => {
  switch (action.type) {
    case "add-student":
      const name = action.payload.name;
      const newStudent = {
        id: Date.now(),
        name,
        isHere: true,
      };

      return {
        count: state.count + 1,
        students: [...state.students, newStudent],
      };
    case "delete-student":
      return {
        count: state.count - 1,
        students: state.students.filter(
          (student) => student.id !== action.payload.id
        ),
      };
    case "mark-student":
      return {
        count: state.count,
        students: state.students.map((student) => {
          if (student.id === action.payload.id) {
            return { ...student, isHere: !student.isHere };
          }
        }),
      };
    default:
      return state;
  }
};

const initialState = {
  count: 0,
  students: [],
};

export default function App() {
  const [name, setName] = useState("");
  const [studentInfo, dispatch] = useReducer(reducer, initialState);

  return (
    <div className="App">
      <h2>출석부</h2>
      <p>총 학생 수 : {studentInfo.count}</p>
      <input
        type="text"
        placeholder="이름을 입력해주세요"
        value={name}
        onChange={(e) => setName(e.target.value)}
      />
      <button
        onClick={() => {
          dispatch({ type: "add-student", payload: { name } });
        }}
      >
        추가
      </button>
      {studentInfo.students.map((student) => {
        return (
          <Student
            key={student.id}
            name={student.name}
            dispatch={dispatch}
            id={student.id}
            isHere={student.isHere}
          />
        );
      })}
    </div>
  );
}
```
