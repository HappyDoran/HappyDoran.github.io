### 1\. HTML 데이터의 수신 \(Incremental Loading\)

- **전체 수신 X, 조각 수신 O:** 서버는 HTML을 **패킷\(Packet\)** 단위로 쪼개서 보냄\.
- **즉각 파싱:** 브라우저는 전체 파일이 다 올 때까지 기다리지 않고, 도착한 조각부터 즉시 읽기 시작함\.

### 2\. DOM 생성 과정 \(Incremental DOM Construction\)

- **순차적 실행:** 렌더링 엔진은 HTML을 위에서 아래로 한 줄씩 읽으며 DOM 트리를 조립\.
- **미완성 상태:** 특정 시점의 DOM은 전체 설계도가 아닌, \*\*&\#39;지금까지 읽은 부분&\#39;\*\*까지만 반영된 상태임\.

### 3\. 자원 호출 시점의 브라우저 상태

#### **A\. CSS \(link 태그\)를 만났을 때**

- **동작:** CSS 파일을 서버에 요청하고 **CSSOM** 생성을 시작\.
- **DOM 상태:** DOM 생성은 멈추지 않고 계속 진행됨\.
- **렌더링 차단:** 단, CSSOM이 완성될 때까지 화면에 그리는 작업\(Paint\)은 중단됨\. \(스타일 없는 화면 노출 방지\)

#### **B\. 자바스크립트 \(script 태그\)를 만났을 때 \(핵심\)**

- **동작:** 스크립트 다운로드 및 실행을 위해 **HTML 파싱을 즉시 중단\(Blocking\)**\.
- **DOM 상태:** ` &lt;script&gt; ` 태그 아래에 있는 HTML 요소들은 아직 DOM 트리에 존재하지 않음\.
- **영향:** JS에서 하단에 있는 DOM 요소를 제어하려 하면 ` null ` 에러가 발생하는 이유임\.

### 4\. 의문점에 대한 결론

> **&quot;HTML이 이미 다 만들어져 있는 상태인가요?&quot;**

- **정답: 아니요\. &quot;읽고 있는 중&quot;이며, &quot;읽은 만큼만&quot; 존재합니다\.**
- **HTML 파일:** 네트워크를 통해 계속 들어오는 중 \(진행형\)\.
- **DOM 트리:** 파서가 읽은 지점까지만 구축된 공사 중인 상태\.
- **JS 실행 시점:** 그 뒤에 올 HTML 내용은 브라우저 입장에서 아직 \*\*&\#39;알 수 없는 영역&\#39;\*\*임\.

### 💡 요약: 공사장 비유

1. **HTML:** 팩스로 한 장씩 들어오는 설계도\.
1. **파서\(인부\):** 설계도를 보며 건물을 짓는 주체\.
1. **DOM:** 현재까지 지어진 건물 골조\.
1. **CSS\(전기 도면\):** 도면 올 때까지 인테리어\(렌더링\) 잠시 중단\.
1. **JS\(외부 기술자\):** 기술자 작업 끝날 때까지 인부가 망치를 내려놓고 공사\(파싱\) 자체를 멈춤\.
