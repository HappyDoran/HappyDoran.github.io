## 참조 타입과 Heap

ARC가 메모리 영역 중 힙 영역을 관리하는 것이기 때문에 중요합니다\. 

Swift가 힙에 메모리를 할당하는 경우는 인스턴스, 클로저 등 ` 참조 타입 `은 자동으로 힙에 할당됩니다\.

```swift
class Human {
    var name: String?
    var age: Int?
    
    init(name: String?, age: Int?) {
        self.name = name
        self.age = age
    }
}

var doran: Human = Human(name: "도란", age: 27) // 지역 변수라고 생각합시다.
```

다음과 같은 코드를 작성했다고 해봅시다\.

Human이란 클래스가 있고, doran이라는 인스턴스를 생성한 후에 initializer를 통해 초기화 했습니다\.

이렇게 했을 때 메모리에 저장은 어떻게 되냐면

![](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-001.jpg>)

지역 변수인 doran은 스택 영역에 할당이 되고, 실제 Human 인스턴스는 힙 영역에 할당이 됩니다\.

스택에 있는 doran은 힙 영역에 있는 인스턴스를 참조하고 있는 형태 입니다\. 

→ doran 안에는 힙에 할당된 인스턴스의 주소값이 있는 형태입니다\.

```swift
var clone = doran
```

이렇게 인스턴스이기 때문에 값을 복사하는 것이 아닌 참조를 하게 되면,

![](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-002.jpg>)

힙이라는 것의 특징중 하나는, ` 사용하고 난 후에는 반드시 메모리 해제를 해줘야 한다는 것 `입니다\.

하지만 우리는 인스턴스를 직접 메모리에서 해제해 준 적은 없습니다\.

스택에 있는 doran, clone이 함수 종료 시점에 사라지고 나면, 

![](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-003.jpg>)

힙에 남은 쓰이지 않는 인스턴스는 메모리에 그대로 남아서 메모리 누수로 이어지는건가요?

아니요\. ` ARC ` 가 해제 해줍니다\.

## ARC가 뭐죠?

> 💡 <strong>공식문서에서의 ARC의 정의</strong>
> 
> Swift는 앱의 메모리 사용량을 추적하고 관리하기 위해 <em>자동 참조 카운팅 \(Automatic Reference Counting\)</em> \(ARC\)를 사용합니다\. 대부분의 경우에 Swift에서 메모리 관리는 &quot;그냥 수행하라&quot; 를 의미하고 메모리 관리에 대해서 생각할 필요가 없습니다\. ` ARC는 인스턴스가 더이상 필요치 않을 때 자동으로 클래스 인스턴스에 의해 사용된 메모리를 할당 해제 ` 합니다\.

→ 그렇다면 ARC는 힙에 할당된 인스턴스의 메모리를 알아서 관리해주는 녀석\.

### Garbage Collection Vs Reference Count

힙 영역의 메모리를 관리하는 방법은 GC와 RC가 있습니다\.

이 둘의 큰 차이점은 참조를 계산하는 시점에 있습니다\.

#### GC\(Garbage Collection\)

참조 계산 시점

- 런타임\. 어플을 실행하는 동안에 주기적으로 참조를 추적하여 사용하지 않는 인스턴스를 해제함

장점

- 인스턴스가 해제될 확률이 높음

단점

- 개발자가 참조 해제 시점을 파악할 수 없음
- 런타임 시점에 계속 추적하는 추가 리소스가 필요하여 성능저하가 발생할 수 있음

#### RC\(Reference Count\)

참조 계산 시점

- 컴파일 타임\. 컴파일 시점에 언제 참조되고 해제되는지 결정되어 런타임 때 그대로 실행됨

장점

- 개발자가 참조 해제 시점을 파악할 수 있음
- 런타임 시점에 추가 리소스가 발생하지 않음

단점

- 순환 참조가 발생 시 영구적으로 메모리가 해제되지 않을 수 있음

### MRC\(MRR\) vs ARC

둘 다 Reference Count이지만 앞에 붙은 Manual, Automatic의 차이입니다\.

MRC는 힙에 있는 메모리를 직접 할당/해제 해주는 것입니다\.\(Objective\-C의 잔여물\)

## ARC의 메모리 관리 방법

ARC는 메모리를 어떻게 관리하길래, 알아서 인스턴스를 해제하는걸까?

ARC의 단점에서 순환 참조는 뭔데 메모리에서 영영 해제되지 않는다는 말일까?

ARC가 메모리를 관리하는 방법은 Reference Count를 이용하는 것입니다\.

> 💡 <strong>Reference Count</strong>
> 
> 메모리의 참조 횟수를 계산하여 참조 횟수가 0이 되면 더이상 사용하지 않는 메모리라 생각하여 해제합니다\.

→ 이 인스턴스를 현재 누가 가르키고 있느냐 없느냐, 누가 참조하고 있느냐 안하냐를 ` 숫자 `로 나타낸 겁니다\.

모든 인스턴스는 자신의 RC값을 가지고 있습니다\. 그렇다면 이 RC를 어떻게 계산할까요?

### Reference Count 계산 \- Count Up

참조 횟수가 \+ 되는 순간은 ` 인스턴스 주소값을 변수에 할당할 때 ` 입니다\.

#### 인스턴스를 새로 생성할 때

![](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-004.jpg>)

다음과 같이 지역변수 doran이 스택에 할당되고 실제 인스턴스는 힙에 할당이 됩니다\. 이때 스택영역에는 힙에 할당된 인스턴스의 주소값이 들어가는데 ` 해당 인스턴스를 “참조” 할 때  `RC가 증가합니다\.

#### 기존 인스턴스를 다른 변수에 대입할 때

![](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-005.jpg>)

다음과 같이 기존의 인스턴스를 다른 변수에 대입하게 되면 ` 해당 인스턴스를 “참조” 할 때 ` 가 되므로 RC가 증가합니다\.

### Reference Count 계산 \- Count Down

#### 인스턴스를 가리키던 변수가 메모리에서 해제 되었을 때

```swift
func makeClone(_ origin: Human) {
    var clone = origin // RC = 2
}

var doran: Human = Human(name: "도란", age: 27) //RC = 1

makeClone(doran)
//RC = 1
```

- doran이 생성되는 순간 인스턴스의 RC가 \+1
- makeClone 함수가 실행되어 clone이 doran을 참조하게 되면 RC가 \+1
- 함수가 끝나고 지역변수 clone이 스택에서 해제가 되는 순간 RC가 \-1이 됩니다\.

![makeClone 함수가 호출되어 지역 변수 clone이 참조를 하는 시점](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-006.jpg>)

![함수가 끝난 후 지역 변수 clone이 메모리가 해제가 되는 시점](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-007.jpg>)

#### nil이 지정되었을 때

```swift
var doran: Human? = Human(name: "도란", age: 27) // RC = 1

var clone = doran // RC = 2

clone = nil // RC = 1
doran = nil // RC = 0
```

이렇게 doran의 RC가 0이 되면 해당 인스턴스는 ARC에 의해 메모리에서 해제될 겁니다\.

#### 변수에 다른 값을 대입한 경우

```swift
var doran: Human? = Human(name: "도란", age: 27) // doran RC = 1
var clone: Human? = Human(name: "도란2", age: 27) //clone RC = 1

doran = clone // doran RC = 0 clone RC = 2
```

#### 프로퍼티의 경우, 속해 있는 클래스 인스턴스가 메모리에서 해제될 때

```swift
class Contacts {
    var email: String?
    var address: String?
    
    init(email: String?, address: String?) {
        self.email = email
        self.address = address
    }
    deinit { print("Contacts Deinit") }
}

class Human {
    var name: String?
    var age: Int?
    var contacts: Contacts? = .init(email: "@pos.idserve", address: "pohang")
    
    init(name: String?, age: Int?) {
        self.name = name
        self.age = age
    }
        
    deinit { print("Human Deinit") }
}
 
var doran: Human? = .init(name: "도란", age: 27)
```

![](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-008.jpg>)

Human이라는 클래스 안에 contacts라는 클래스 인스턴스가 프로퍼티로 존재합니다\.

따라서 Human 인스턴스 doran을 생성하게 되면 Contacts 인스턴스도 생성되어 각각의 RC가 증가합니다\.

하지만 doran에 nil을 할당하게 되는 순간,

```swift
doran = nil
```

![](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-009.jpg>)

doran이 가리키던 인스턴스 메모리가 해제되고, Human 인스턴스의 RC가 1 감소합니다\.

![](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-010.jpg>)

Human 인스턴스의 RC가 0이 되었으므로 메모리에서 해제가 되고 contacts가 참조하고 있는 Contacts 인스턴스의 RC가 1 감소합니다\.

![](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-011.jpg>)

Contacts 인스턴스의 RC도 0이 되기 때문에 메모리에서 해제 됩니다\.

그래서 위의 콘솔을 찍어보면\.

![](<../../assets/blog/arc-88d631183db446a3aa37d37e5d3c3fb2/image-012.png>)

다음과 같이 Human 인스턴스가 먼저 소멸 되고 그 이후에 Contacts 인스턴스가 소멸되는 것을 볼 수 있습니다\.
