<strong>실행 컨텍스트</strong>는 자바스크립트에서 코드가 실행되는 환경을 의미합니다\.
자바스크립트 엔진이 코드를 실행할 때, 그 코드가 실행될 때의 환경을 정의하고 관리하기 위해 존재하는 것이 실행 컨텍스트입니다\.

실행 컨텍스트는 크게 <strong>전역 실행 컨텍스트</strong>와 <strong>함수 실행 컨텍스트</strong>로 나눌 수 있습니다\.

<strong>전역 실행 컨텍스트</strong>는 자바스크립트가 처음 실행될 때 생성되는 컨텍스트입니다\.
이 전역 컨텍스트는 프로그램이 종료될 때까지 유지되며, 전역에 선언된 변수나 함수가 모두 포함됩니다\. 전역 컨텍스트에서 선언된 변수와 함수는 프로그램 내 어디서든 접근이 가능합니다\.

기본적으로 자바스크립트는 싱글 스레드이기 때문에, 전역 실행 컨텍스트는 1개만 존재합니다\.

<strong>함수 실행 컨텍스트</strong>는 함수가 호출될 때마다 생성 되는 컨텍스트를 의미합니다\.
각 함수는 자신만의 실행 컨텍스트를 가지며, 이 컨텍스트 내에서 선언된 변수와 함수는 해당 함수 내에서만 유효합니다\. 함수가 종료되면 그 실행 컨텍스트도 함께 사라집니다\.

### 실행 컨텍스트는 어떤 구성 요소로 이루어져 있나요? 🤔

실행 컨텍스트는 크게 ` 변수 객체 `, ` 스코프 체인 `, ` this ` 라는 구성 요소로 이루어져 있습니다\.

첫째, <strong>변수 객체</strong>란 실행 컨텍스트 내에서 사용되는 변수와 함수 선언을 저장하는 공간입니다\. 전역 컨텍스트에서는 전역 객체가 변수 객체의 역할을 하고, 함수 컨텍스트에서는 <strong>활성 객체</strong>가 변수와 매개변수를 관리합니다\.

둘째, <strong>스코프 체인</strong>입니다\. 현재 실행 중인 컨텍스트와 외부 렉시컬 환경의 연결을 유지합니다\.
변수를 참조할 때 현재 컨텍스트에서 찾지 못하면 외부 환경으로 범위를 넓혀가며 변수를 찾습니다\.

마지막으로, <strong>this</strong>입니다\. <strong>this</strong>는 실행 컨텍스트에 따라 참조하는 객체가 달라집니다\.
전역 컨텍스트에서는 this가 전역 객체를 가리키며, 함수 컨텍스트에서는 함수 호출 방법에 따라 달라집니다\.

실행 컨텍스트는 이러한 구성 요소를 바탕으로 자바스크립트 코드가 실행되는 동안의 환경을 관리하고, 코드 실행 시 변수의 유효 범위나 함수 호출의 맥락을 결정 짓습니다\.

## 면접 답변

#### 💡 \[버전 1\] 핵심만 찌르는 두괄식 답변 \(추천\)

> <strong>&quot;실행 컨텍스트는 자바스크립트 코드가 평가되고 실행되는 환경을 추상화한 객체로, 코드 실행에 필요한 변수, 함수 선언, 스코프, this 정보를 담고 있는 영역입니다\.&quot;</strong>

실행 컨텍스트는 처음 실행 시 생성되는 유일한 <strong>전역 컨텍스트</strong>와, 함수가 호출될 때마다 독립적으로 생성되는 <strong>함수 컨텍스트</strong>로 나뉘며 실행 스택\(Call Stack\)을 통해 관리됩니다\.

내부 구조는 크게 세 가지 핵심 요소로 구성됩니다\.

1. <strong>변수 객체\(Variable Object\)</strong>: 매개변수\(arguments\), 변수, 함수 선언을 저장하는 공간입니다\.
1. <strong>스코프 체인\(Scope Chain\)</strong>: 현재 컨텍스트와 상위 렉시컬 환경의 연결 리스트로, 변수 식별자를 검색하는 경로가 됩니다\.
1. <strong>this 바인딩</strong>: 함수 호출 방식에 따라 결정되는 ` this ` 식별자가 참조할 객체를 저장합니다\.

#### 📝 \[버전 2\] 꼬리 질문을 방어하는 상세 답변

> <strong>&quot;실행 컨텍스트는 자바스크립트 엔진이 코드를 실행하기 위해 필요한 식별자와 스코프를 관리하는 물리적인 객체입니다\. 자바스크립트의 핵심 동작인 호이스팅, 클로저, 스코프 체이닝이 모두 이 실행 컨텍스트를 기반으로 일어납니다\.&quot;</strong>

면접관님께서 질문하신 실행 컨텍스트의 내부 동작과 구성을 조금 더 상세히 말씀드리면, 하나의 컨텍스트는 <strong>생성\(평가\) 단계</strong>와 <strong>실행 단계</strong>를 거치며 변수 객체, 스코프 체인, this를 정립합니다\.

- <strong>변수 객체와 호이스팅 방어</strong>: 생성 단계에서 엔진은 코드를 훑으며 변수와 함수 선언을 변수 객체\(실행 컨텍스트 환경\)에 먼저 등록합니다\. 이 과정 때문에 선언문보다 위에서 함수를 호출해도 정상 작동하는 <strong>호이스팅</strong> 현상이 발생합니다\.
- <strong>스코프 체인을 통한 외부 환경 참조</strong>: 각 컨텍스트는 자신이 선언된 외부 렉시컬 환경에 대한 참조를 가집니다\. 식별자를 현재 컨텍스트의 변수 객체에서 찾지 못하면, 이 스코프 체인을 따라 전역 객체까지 상위로 타고 올라가며 검색합니다\. 이 메커니즘 덕분에 외부 함수의 실행이 종료되어도 내부 함수가 상위 스코프를 기억하는 <strong>클로저</strong>가 가능해집니다\.
- <strong>호출 방식에 동적인 this 결정</strong>: 컨텍스트 내부의 ` this `는 선언 시점이 아닌, <strong>함수가 어떻게 호출되었느냐</strong>에 따라 실행 단계에서 동적으로 바인딩되므로, 전역 호출, 메서드 호출, 생성자 함수 호출 등에 따라 가리키는 객체가 달라집니다\.
