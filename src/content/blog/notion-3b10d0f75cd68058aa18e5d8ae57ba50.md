### 문서 목적

Native image lifecycle, Web orchestration, object storage upload와 asynchronous analysis request의 책임 분리를 설명한다\. Field\-level contract는 ` 랜드마크 기반 이미지 분석 API 계약 ` 문서를 기준으로 한다\.

### 2\. Native capture lifecycle

1. 카메라 또는 앨범 사진 확보와 포즈 자동 검출
1. 방향을 up으로 반영하고 긴 변 최대 2048px JPEG로 정규화
1. 고정 순서 9점 생성·파생, 못 찾은 점은 initialized로 표시
1. 리뷰에서 확인·조정하고 initialized가 남으면 완료 거부
1. 최종 바이트의 SHA\-256·크기·해상도 생성
1. ` capture_<uuid> ` 발급과 임시 파일 registry 등록
1. 메타데이터·미리보기·9점만 Web에 반환

로컬 파일 경로는 결과 계약으로 노출하지 않는다\. App 밖 브라우저도 ` capture_web-<uuid> `와 동일한 결과 계약을 만들며 사진은 페이지 메모리에 둔다\.

### 3\. Bridge 흐름

```text
REQUEST_POSE_CAMERA
  -> Native open()
  -> POSE_CAMERA_COMPLETED | POSE_CAMERA_CANCELLED

REQUEST_CAPTURE_IMAGE_UPLOAD
  -> Native uploadCapture(captureId, url, method, headers)
  -> CAPTURE_IMAGE_UPLOAD_COMPLETED | FAILED
```

App과 Web은 동일한 Zod schema로 result shape를 검증한다\. Async upload response는 ` captureId `와 ` uploadId `가 모두 일치할 때만 pending Promise를 완료한다\.

### 4\. Web orchestration

현재는 실제 HTTP 경로를 사용한다\.

```text
IDLE → CAPTURE_READY → REQUESTING_UPLOAD_URL → UPLOADING_IMAGE
     → SUBMITTING_ANALYSIS → POLLING_ANALYSIS
오류 → FAILED
```

Zustand는 준비 작업만 소유하고 서버 분석 상태는 TanStack Query의 running/succeeded/failed로 분리한다\. ` prepareBodyAnalysis `가 업로드 세션 생성 → PUT → 분석 생성 → 캡처 해제를 실행한다\. 단건 query는 running일 때 2초 간격, 클라이언트 최초 관측부터 3분까지 조회한다\. 한도 뒤에는 수동 재확인 또는 내역에서 확인한다\. 완료 결과를 받으면 navigation lock 해제를 기다려 Result로 replace한다\.

현재 runtime에 mock 업로드·분석 adapter는 없다\. 예시 결과 ID도 제거되었으며 테스트만 응답 fixture를 쓴다\.

### 6\. Temporary file와 release

native registry는 24시간 지난 기록을 다음 등록 때 정리한다\. Web은 분석 생성 성공 후 ` releaseNativeCaptureImage `를 호출하며 새 촬영과 처음부터 다시 시작에서도 이전 이미지를 해제한다\. 브라우저 capture는 같은 함수가 메모리에서 제거한다\.

제출 성공 여부가 불명확한 오류에서 POST 전체를 자동 반복하지 않는다\. 새 세션을 만들면 분석이 중복 생성될 수 있다\. 실패·취소 object 보존 및 URL 만료 후 재발급은 아직 정해지지 않았다\.

### 8\. Concurrency

- Upload Promise는 request의 two identifiers로 다른 response를 무시한다\.
- Default timeout은 60초다\.
- Native registry lookup과 upload는 local file 존재를 다시 확인한다\.
- Web loading Activity는 ` hasStartedRef `로 initial duplicate execution을 차단한다\.
- Navigation lock은 transition 중 중복 route action을 차단한다\.

### 9\. Security

- 사전서명 URL과 headers는 응답 그대로 사용하며 클라이언트가 host를 치환하지 않는다\.
- native 원본 바이트·로컬 경로를 분석 JSON에 넣지 않고 바이너리 PUT을 쓴다\. 미리보기 data URL은 Web UI 전용이다\.
- 브라우저 직접 PUT에는 저장소 CORS 허용과 HTTPS/[localhost](<http://localhost/>) checksum 생성이 필요하다\.
- 토큰은 BFF HttpOnly cookie에만 두며 사전서명 URL·사진·치수·토큰을 로그에 남기지 않는다\.
- FE schema·테스트는 서버의 object 검증·보존 정책이 구현되었다는 증거가 아니다\.

### 10\. Validation checklist

현재 자동 검증은 shared 9점 schema, builder·경계값, captureId/uploadId 상관관계, 준비 오케스트레이션, polling·실패 문구, 화면 이동과 이탈 후 결과 무시를 포함한다\.

실기기 권한·촬영·native PUT, 저장소 CORS·URL 만료, 실패·취소 object 보존은 별도 검증·합의 영역이다\. 이번 문서 갱신에서 이를 통과로 표시하지 않는다\. 자세한 최신 흐름은 체형 분석 비동기 흐름 설계와 네이티브 포즈 카메라 설계를 함께 본다\.
