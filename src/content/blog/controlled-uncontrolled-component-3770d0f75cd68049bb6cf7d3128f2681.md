<strong>Controlled Component</strong>는 리액트 상태\(` state `\)를 통해 입력 값을 제어하는 컴포넌트를 말합니다\.
이 방식에서는 입력 요소의 값\(` value `\)을 리액트 상태와 동기화하고, 사용자가 입력을 변경할 때마다 ` onChange ` 이벤트 핸들러를 통해 상태를 업데이트합니다\. Controlled Component는 값이 리액트의 ` state `로 관리되므로, 입력 시마다 값을 검증하거나, 값을 자유롭게 변경할 수 있으며, 복잡한 폼 로직을 처리하는 데 유용합니다\.

<strong>Uncontrolled Component</strong>는 입력 값을 리액트의 상태로 관리하지 않고, DOM을 통해 입력 값을 제어하는 방식입니다\. 즉, 입력 요소의 값은 DOM에서 직접 관리되며, 리액트는 이를 제어하지 않습니다\. 이 방식에서는 ` useRef `를 사용해 생성된 참조 객체인 ` ref `를 사용하여 DOM 요소에 직접 접근하여 값을 읽거나 조작합니다\. Uncontrolled Component는 리액트 상태 관리에 따른 성능 비용이 없으므로 상대적으로 간단한 폼에서 주로 사용됩니다\.

### Controlled Component와 Uncontrolled Component는 각각 어떤 상황에서 사용되나요? 🤔

단순한 입력 필드가 포함된 폼에서는 입력 요소의 값을 리액트 상태로 관리할 필요성이 적으므로, Uncontrolled Component를 사용하는 것이 더 간단하고 성능이 좋습니다\. 사용자가 제출 버튼을 클릭했을 때만 입력 값을 가져와도 충분한 경우를 예시로 들 수 있습니다\.

반면, 값을 입력할 때마다 유효성 검증을 실시간으로 해주어야 하는 경우에는 Controlled Component를 사용해야 합니다\.

## 면접 답변

#### 💡 \[버전 1\] 핵심만 찌르는 두괄식 답변 \(추천\)

> <strong>&quot;제어 컴포넌트는 입력값을 리액트의 &\#39;상태\(state\)&\#39;로 관리하는 방식이며, 비제어 컴포넌트는 리액트 상태를 거치지 않고 &\#39;DOM\(ref\)&\#39;에서 입력값을 직접 관리하고 추출하는 방식입니다\.&quot;</strong>

두 방식은 데이터의 신뢰할 수 있는 단일 원천\(Single Source of Truth\)을 어디에 두느냐에 따라 나뉘며, 요구사항에 맞춰 선택적으로 사용합니다\.

- <strong>제어 컴포넌트 \(State 기반\)</strong>: ` value ` 속성과 ` onChange ` 이벤트를 바인딩하여 입력값을 실시간으로 동기화합니다\. 실시간 유효성 검사, 조건부 제출 버튼 활성화, 입력 양식 포맷팅\(예: 전화번호 하이픈 자동 삽입\) 등 <strong>동적이고 복잡한 UI 폼</strong>에 필수적입니다\.
- <strong>비제어 컴포넌트 \(DOM/Ref 기반\)</strong>: ` useRef `를 통해 필요할 때만\(예: 제출 시점\) DOM에서 값을 읽어옵니다\. 매 입력마다 리렌더링이 발생하지 않으므로 <strong>단순한 로그인/회원가입 폼</strong>이나 대량의 입력 필드가 있어 <strong>성능 최적화가 중요한 상황</strong>에 유리합니다\.

#### 📝 \[버전 2\] 꼬리 질문을 방어하는 상세 답변

> <strong>&quot;제어 컴포넌트와 비제어 컴포넌트는 입력창에 담긴 유저의 데이터 흐름을 리액트 엔진의 라이프사이클 안으로 끌고 들어올 것인가, 아니면 브라우저 고유의 영역에 맡겨둘 것인가의 차이입니다\.&quot;</strong>

면접관님께서 질문하신 &\#39;적절한 활용 상황&\#39;과 더불어, 실무 관점에서의 장단점 및 트레이드 오프\(Trade\-off\)를 고려하여 구체적으로 말씀드리겠습니다\.

- <strong>제어 컴포넌트의 한계와 방어</strong>: 제어 컴포넌트는 리액트가 폼의 상태를 완벽히 통제할 수 있다는 강력한 장점이 있지만, 키보드를 누를 때마다\(타이핑마다\) 컴포넌트 전체가 리렌더링된다는 비용이 발생합니다\. 만약 하나의 대형 폼 컴포넌트에 수십 개의 입력 필드가 존재한다면 사소한 타이핑에도 화면이 버벅거릴 수 있으므로, 하위 컴포넌트로 폼을 잘게 쪼개거나 디바운싱\(Debouncing\) 등의 추가 최적화가 필요합니다\.
- <strong>비제어 컴포넌트의 가치와 실무 활용</strong>: 반면 비제어 컴포넌트는 &\#39;제출\(Submit\) 버튼을 누르기 전까지는 리액트가 입력값에 관심이 없는&\#39; 구조입니다\. 불필요한 리렌더링을 원천 차단하므로 성능상 매우 가볍습니다\. 또한 파일 업로드\(` .type = "file" `\) 엘리먼트처럼 브라우저 보안상 리액트의 state로 값을 임의 변경할 수 없는 경우, 반드시 비제어 방식을 사용해야 합니다\.
- <strong>결론 및 아키텍처적 선택</strong>: 따라서 저는 실시간 피드백이 중요한 &\#39;검색어 자동완성&\#39;이나 &\#39;비밀번호 강도 체크&\#39; 등에는 <strong>제어 컴포넌트</strong>를 도입하고, 작성이 완료된 후 전송만 하면 되는 &\#39;단순 피드백 폼&\#39;이나 &\#39;기본 로그인 페이지&\#39;에는 <strong>비제어 컴포넌트</strong> 혹은 대규모 폼 관리 라이브러리\(React Hook Form 등\)를 도입하여 성능과 개발 생산성의 균형을 맞추고 있습니다\.
