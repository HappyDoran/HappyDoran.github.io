React의 입력 컴포넌트는 값을 React state로 관리할지, DOM에 두고 필요한 시점에 읽을지에 따라 나눌 수 있다\. 값의 소유 위치와 입력 중 피드백 요구를 기준으로 두 방식을 비교한다\.

### Controlled Component

입력 value를 state와 연결하고 onChange에서 상태를 갱신한다\. 입력할 때마다 유효성 검사, 제출 버튼 활성화, 형식 변환 같은 UI를 계산하기 쉽다\.

state 변경은 렌더링 비용과 연결된다\. 큰 폼에서 입력 하나가 넓은 화면의 렌더링을 일으킨다면 컴포넌트 분리와 입력 처리 범위를 검토해야 한다\. 필요에 따라 디바운싱도 고려할 수 있다\.

### Uncontrolled Component

입력값은 DOM이 관리하고 ref로 필요한 시점에 읽는다\. 제출 시점에만 값이 필요하다면 매 입력을 state에 반영하는 구조를 줄일 수 있다\.

입력마다 React 상태를 갱신하지 않는다는 이점이 있지만 모든 폼이 자동으로 더 빠르거나 구현이 간단해진다고 단정하지 않는다\. 제출 전 검증·오류 표시·다른 UI와의 연동 요구도 함께 본다\.

검색어 자동완성·비밀번호 강도 표시처럼 입력 중 피드백이 필요한 경우와, 제출 시점에 값을 수집하는 단순 폼은 다른 기준으로 선택할 수 있다\.

파일 입력은 일반 텍스트 입력처럼 state로 임의의 파일 값을 지정하는 모델과 다르다\. 브라우저가 제공하는 파일 선택 흐름을 따른다\.

### 트레이드오프

제어 방식은 state를 중심으로 데이터 흐름을 추적하기 쉽고 동적인 UI를 구성하기 좋다\. 비제어 방식은 입력 자체와 React 갱신의 결합을 줄이지만 필요한 시점의 값 수집과 검증을 명시해야 한다\.

폼 관리 라이브러리를 사용하더라도 입력값의 소유 위치와 업데이트 범위를 이해해야 한다\. 도구 이름만으로 제어·비제어의 비용이 사라지지는 않는다\.

### 정리

두 방식의 차이는 입력값의 원본을 어디에 두는가다\. 실시간 피드백, 값 수집 시점, 렌더링 범위, 파일 입력 제약을 기준으로 선택한다\.
