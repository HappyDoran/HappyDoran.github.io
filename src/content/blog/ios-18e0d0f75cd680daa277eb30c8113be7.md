안녕하세요, HMHZ Studio 개발 팀에서 iOS / Frontend 개발을 하고 있는 도란입니다\. 이번 글에서는 iOS 앱에서 안전하고 효율적인 토큰 기반 인증 시스템을 구현한 방법을 설명하고, Access Token과 Refresh Token을 사용한 인증 흐름과 키체인을 활용한 암호화된 데이터 저장 공간 구현에 대해서 얘기보겠습니다\.

## 개요

개발자의 시선에서 봤을 때 인증인가 부분은 너무 어려운 이야기라고 생각됩니다\. 어떤 방법으로 보안을 강화해야하고, 왜 이 방법이 적절한지에 대해서 끊임없이 생각해야 하는 대목이라고 생각해야 하니까요\. 

이를 위해 저희 팀은 다음과 같은 목표를 가지고 인증 시스템을 설계 했습니다\.

1. 직관적인 코드 구성 : 인증 및 인가의 흐름이 개발자들이 이해 가능한 수준으로 구현
1. 보안성 : 토큰의 안전한 저장과 관리
1. 명확한 에러처리와 동시성 제어: 에러 처리와 동시성 제어를 명확하게 구현

## AccessToken과 RefreshToken

AccessToken은 보안을 위한 유효기간이 짧은 토큰, 사용자의 개인정보에 접근하는데 사용되고, RefreshToken은 유효기간이 비교적 긴 토큰, 액세스 토큰 만료시 갱신을 위한 목적으로 주로 사용됩니다\. 

즉 평소에는 AccessToken만 가지고 서버와의 통신을 하다 AccessToken이 만료가 되면 RefreshToken을 매개변수로 새로운 AccessToken을 받아와서 쓰는 흐름으로 구현이 됩니다\. 

## 프로세스

프로젝트 내부에서 토큰을 다룰 때의 고려해야할 점은 다음과 같습니다\.

- 앱 로그인 시
- 앱에 자동 로그인 시
- 앱 사용 중
- 앱 사용 중 Access Token이 만료 되었을 경우
- 앱 사용 중 Refresh Token이 만료 되었을 경우

### 구체적으로 설명해보기

#### 앱 로그인 시

1. 사용자가 Apple 로그인을 시도합니다\.
   1\-1\.  클라이언트 ↔ 서버의 관계가 아닌 클라이언트 ↔ 리소스\(Apple\)의 관계로 사용자 정보를 가져옵니다\.
1. Apple 로그인을 통해 받아온 정보\(E\-mail, Authorization Code 등\)을 서버로 보냅니다\.
1. 로그인 인증을 허용받은 클라이언트는 서버로부터 Access Token, Refresh Token을 받습니다\.
1. 클라이언트는 Access Token과 Refresh Token을 로컬에 저장합니다\.
1. Access Token의 만료 시간은 서버에서 관리하는 것이 아닌 클라이언트에서 관리합니다\.

#### 앱 자동 로그인 시

1. 앱 실행시 로컬에 Refresh Token을 가져옵니다\.
1. Refresh Token이 있을 경우,
   2\-1\.  서버에 새로운 Refresh Token과 Access Token을 요청합니다\.
   
   2\-2\.  Access Token을 로컬에 저장합니다\.
   
   2\-3\.  사용자 정보를 업데이트 합니다\.
1. Refresh Token이 없거나, 만료된 경우,
   3\-1\. 앱 로그인 화면으로 보내버립니다\.

> 📌 왜 자동 로그인 시에 Refresh Token을 갱신 받아야 하는걸까요?
> 
> Refresh Token의 경우 Access Token을 갱신하기 위해서 사용됩니다\. 즉, 앱 내부에 들어가게 되면 서버와의 API 통신시에 거의 대부분 Access Token을 가지고 통신을 하죠\.
> 
> 
> 이 Access Token이 만료되게 되면 Refresh Token을 통해 새로운 Access Token을 발급해주는 겁니다\. 그러므로 Refresh Token의 갱신 시점은, 앱의 수명주기가 시작될 때, 즉 앱에 진입시에 해주는 것이 제일 베스트입니다\.

#### 앱 사용중

1. 사용자의 정보가 필요한 API 통신의 경우 로컬의 Access Token을 헤더에 넣어서 API 통신을 합니다\.
1. 앱 사용중 Access Token이 만료된 경우,
   2\-1\.  Access Token을 사용하여 서버와 통신할 때마다 확인해줍니다\.
   
   2\-2\. 만료시간이 지나서 Access Token이 만료된 경우, 로컬에서 Refresh Token을 조회합니다\.
   
   2\-3\. 가져온 Refresh Token을 서버로 보내서 새로운 Access Token을 가져옵니다\.
   
   2\-4\. 새로 받은 Access Token을 로컬에 저장합니다\.
1. 앱 사용 중 Refresh Token이 만료된 경우,\(거의 그럴리는 없겠지만…\)
   3\-1\.  앱 로그인 화면으로 보내버립니다\.
