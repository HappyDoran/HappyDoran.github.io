### 목적

초기 mock 준비 단계의 체크리스트를 현재 구현 기준으로 갱신한다\. 검토 기준은 ` 645a584 `와 관련 source이며, 문서 갱신 과정에서 실제 저장소 PUT·네이티브 SDK를 재실행한 것은 아니다\.

### 구현 완료

- [x] ` captureId `·메타데이터·SHA\-256 생성, native 임시 파일 registry와 해제 브리지
- [x] JPEG 긴 변 최대 2048px 정규화, 방향·반전 반영
- [x] 9점 고정 순서: headTop, leftShoulder, rightShoulder, leftWaist, rightWaist, leftHip, rightHip, leftAnkle, rightAnkle
- [x] 카메라·앨범 포즈 검출과 리뷰 조정, 미확인 initialized 제출 차단
- [x] 요청 builder와 cm → mm 변환, 키·선택 몸무게 범위 검증
- [x] HttpOnly cookie BFF 인증과 보호 API refresh
- [x] 실제 업로드 세션 API → native 또는 브라우저 PUT → 분석 생성
- [x] 분석 단건 2초 polling, 관측 시점 기준 3분 한도와 수동 재확인
- [x] 분석 생성 성공 후 촬영 이미지 해제, 다시 시작 시 해제
- [x] 서버 상태 running/succeeded/failed, 코드별 실패 문구와 횟수 초과 안내
- [x] 대표 지정·선택 삭제·공개 결과 공유
- [x] App 밖 브라우저 사진 선택·검출·조정 경로
- [x] builder·schema·오케스트레이션·query·화면 분기 테스트

### HTTP contract 확정 후

실제 HTTP 연결은 완료되었다\. 아래는 연결 이후에도 남은 검증·운영 항목이다\.

- [ ] OpenAPI 생성 코드로 전환할 수 있는지 응답 계약 최종 대조
- [ ] 대상 환경·실기기에서 object storage PUT 전체 흐름 재검증
- [ ] 사전서명 URL 만료 후 자동 재발급 정책
- [ ] 제출 결과가 불명확한 오류의 중복 방지·복구 계약
- [ ] 미완료 object와 실패·취소 파일 보존 정책 합의

### 결정 필요

현재 확정해 소비하는 값: 업로드 ` /api/v1/body-analysis-uploads `, 분석 ` /api/v1/body-analysis `, Bearer 인증\(BFF에서만 전달\), 15MiB 상한, schemaVersion·landmarkSet\.version 1, 9점 순서, 2초 polling과 서버 상태 3종이다\.

남은 결정은 실패·취소 object 보존, URL 재발급, 제출의 idempotency, 출시 전 이미지·치수 접근·보존·동의 정책이다\. ` Idempotency-Key ` 전송이나 SSE/WebSocket은 현재 구현하지 않았다\.

### 완료 기준

코드의 준비 흐름은 capture → upload session → 바이너리 PUT → 분석 제출 → 단건 polling → 실제 결과 화면이다\. mock adapter 전환 작업은 더 이상 남은 작업이 아니다\. 자동화는 builder·경계·오케스트레이션을 검증하며 Native SDK·권한·실기기 PUT는 별도 검증한다\. 근거는 ` body-analysis.mutation.ts `, ` body-analysis.query.ts `, ` body-analysis.schema.ts `, ` packages/shared/src/pose.ts `다\.
