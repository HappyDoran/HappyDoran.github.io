### 1\. 목표

기존의 WebView에서 input으로 처리하던 이미지 업로드를 Native 환경에서 구현하여, 이미지 선택 및 크롭을 진행한다\.

### **2\. 요구사항**

- 이미지 피커의 UI를 **커스텀 가능**하게 구현
- 선택한 이미지의 **메타데이터\(위치좌표, 날짜, EXIF 등\) 보존**
- 선택한 이미지를 9:16 비율로 **크롭 가능**
- 크롭 진행 시 이미지 영역 내에서 **크롭 영역과 스케일 조절 가능**
- 원본 갤러리 순서 유지

### 3\. 기술 검토

#### 3\.1\. camera\-roll

**장점:**

- UI 커스텀 범위가 넓음
- Android에서 메타 데이터 취득 가능 \(iOS는 가상 경로로 인해 URI로 메타 데이터 취득 불가\)
- 페이지네이션을 통한 대용량 갤러리 처리 가능
- 선택한 이미지의 순서 관리 용이

**단점:**

- 이미지의 base64 처리가 번거로움
- base64 처리 시 이미지 용량이 2~3배 증가
- 이미지 원본 보존 불가 \(가상 경로\)
- iOS와 Android를 다른 Native Module로 각각 관리해야 함

#### 3\.2\. react\-native\-image\-picker

**장점:**

- native\-picker를 사용하여 안정적
- base64 처리 자동화
- 이미지 원본 보존 가능

**단점:**

- UI 커스텀 범위가 제한적
- 메타데이터\(EXIF 데이터\) 접근이 어려움
- 메타데이터 읽기 위해 react\-native\-exif 추가 필요 \(의존성\)
- 다중 선택 시 UI 제어 어려움

#### 3\.3\. react\-native\-image\-crop\-picker

**장점:**

- native\-picker 사용으로 안정적
- EXIF 데이터를 가져오는 내장 로직 존재
- 크롭 기능 내장

**단점:**

- UI 커스텀 범위가 제한적
- 요구사항에 맞는 image\-picker UI 구현 불가
- 다중 선택 시 개별 크롭 처리 복잡

### 4\. 결론 및 구현 방향, 핵심 라이브러리

#### 4\.1\. 구현 방향

- **camera\-roll 라이브러리로 커스텀 UI 구현**
   → 커스텀 UI 구현 비용이 메타데이터 보존 로직 구현 비용보다 낮음
- 이미지 메타데이터와 크롭 영역 지정은 **Native Module에서 처리**
- **React Native Reanimated**를 활용한 부드러운 제스처 처리를 통해 크롭 UI 구현
- **Gesture Handler**를 통한 드래그 및 핀치 제스처 구현을 통해 크롭 UI 구현

#### 4\.2\. 핵심 라이브러리

- **@react\-native\-camera\-roll/camera\-roll**: 갤러리 접근 및 이미지 로드
- **react\-native\-reanimated**: 부드러운 애니메이션 및 제스처 처리
- **react\-native\-gesture\-handler**: 드래그 및 핀치 제스처
- **react\-native\-safe\-area\-context**: 안전 영역 처리

### 5\. 구현

#### 5\.1\. camera\-roll을 이용한 Custom\-image\-picker 구현

#### 5\.1\.1\. 각 이미지의 정보를 담는 PhotoAsset 구현

- 이미지의 URI, 너비, 높이, 크롭 영역에 필요한 좌표, 스케일 값 등의 타입 구현

#### 5\.1\.2\. 이미지 선택 및 상태 관리

- **최대 4장 선택 제한**
- **자동 초기화**: 선택 시 자동으로 9:16 크롭 영역과 최소 스케일 계산
- **메인 이미지 관리**: 현재 표시 중인 이미지 추적
- **페이지네이션**: 50장씩 로드하여 대용량 갤러리 처리

#### 5\.1\.3\. 9:16 크롭 영역 자동 계산

- 가로로 긴 이미지, 세로로 긴 이미지에 따라서 이미지를 자르고, 크롭 영역을 이미지 중앙으로 배치

#### 5\.2\. React Native Reanimated를 이용한 메인 이미지 영역 드래그

#### 5\.2\.1\. 제스처 처리 구조

- **크롭 영역은 중앙에 고정**시킨 상태에서 이미지를 드래그하여 영역 지정
- **드래그 \+ 핀치 제스처 동시 처리** \(Gesture\.Simultaneous\)
- **크롭 영역이 이미지의 범위를 벗어나지 않도록 클램핑** \(스프링 애니메이션\)

#### 5\.2\.2\. 최소 스케일 보장

- **이미지가 크롭 영역을 완전히 채우는 최소 스케일 계산**
- **축소 시 저항감 제공**하여 크롭 영역이 비지 않도록 보장
- **최대 스케일 제한** \(3\.0배\)으로 과도한 확대 방지

#### 5\.3\. 크롭 영역 계산 및 변환

#### 5\.3\.1\. 이미지 변환 정보를 크롭 영역으로 변환

- 이미지의 크기, 스케일 값, 크롭 영역 이동을 좌표로 변환하여 최종 크롭 영역을 계산
- 계산된 크롭 영역의 x,y 좌표, 너비, 높이를 Native Module로 전달

#### 5\.4\. 크롭된 이미지에 메타데이터 복사 붙여넣기

#### 5\.4\.1\. JS → Native Module로 데이터 전달

- Native Module에서 원본 이미지의 메타데이터 추출

#### 5\.4\.2\. iOS 메타데이터 보존 처리

- 원본 이미지의 메타데이터 추출
- CGImage로 크롭 수행
- 크롭된 이미지에 메타데이터 주입
- 갤러리 저장

#### 5\.4\.3\. Android 메타데이터 보존 처리

- 원본 이미지의 EXIF 메타데이터 추출
- Bitmap으로 크롭 수행
- 크롭된 이미지에 메타데이터 주입
- 갤러리 저장

#### 5\.4\.4\. 보존되는 메타 데이터

- **EXIF 데이터**: 카메라 설정 \(ISO, 노출시간, F값, 초점거리 등\)
- **GPS 정보**: 위치, 고도, 정확도
- **시간 정보**: 촬영일, 수정일 \(크롭 시점으로 업데이트\)
- **카메라 정보**: 제조사, 모델명
