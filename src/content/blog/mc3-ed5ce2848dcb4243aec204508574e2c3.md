## HTTPMethod\.swift

- get, post 등 정의
- “\\\(\)”를 표시하기 위한 CustomStringConvertible 프로토콜 채택

## URLComposable\.swift

- URLComponents\(\)라는 타입이 Swift에 있음
   → 이걸 토대로 프로젝트에서 필요한 스킴\(http,https\), 호스트, 포트 번호, path를 받아서 만듬\. 
- 이걸 토대로 URL을 만듬

> 💡 **URLComponents\(\) 검색해볼 것**

Protocol은 기본적으로 함수나 연산 프로퍼티를 지정해줄 수 없는데 Extension을 통해서 함수나 연산 프로퍼티를 만들어 줄 수 있다\.

## HTTPRequestable\.swift

- URLComposable 상속
   → 프로퍼티나 메소드에 접근이 가능\(ex configureURL\(\)\)
- Request를 하는 프로토콜 역할을 합니다\.

```swift
// 직접 console 찍어보면 되겠다.
var request = URLRequest(url: url)
        request.httpMethod = "\(httpMethod)" //Get,Post 등
        request.allHTTPHeaderFields = headerFields //헤더 필드가 있겠지 뭐
```

## PartyRouter\.swift

- 방과 관련된 Request들을 다 만드는 파일
- enum으로 방 만들 때 필요한 parameter를 받음
- 각각의 case 별로 httpMethod, baseHost\(Git에서 못보게 ignore 처리\)
   ```swift
   BASE_HOST = ""
   -> AppEnvironment.swift에서 정의
   ```

> 💡 **\_의 의미**
> 
> 아무것도 안주는게 맞으니까 뭐 없다고 찡찡대지마라\.

- query가 들어가는 makeParty와 enterParty에만 저렇게 query를 넣어주고 나머진 nil

## MessageRouter\.swift

- json 형태로 보내기 때문에 header가 있어야 함\.
- 위와 Flow는 비슷

## DataFetchable\.swift

- DataFetchable 프로토콜을 생성함으로써 Data를 가지고 오는 함수를 제네릭으로 구현하게 선언

## ResponseProcessProtocol\.swift

- Router를 받으면 Router를 가지고 데이터를 반환하는 함수
- Response를 처리해서 Data만 가지고 오게끔 처리\.

## HttpService\.swift

- DataFetchable을 채택하여 이벤트가 발생하게 되면 실제로 행해지는 제네릭 메소드를 구현

### 정리

DataFetchable: HttpService에서 바깥에 보여지는거에서 사용하는 함수 선언

ResponseProcessProtocol: 실제로 Request, Response 해오는 안쪽의 과정을 구현

HttpService: DataFetchable을 채택한 이벤트 발생할 때 행해지는 그런 함수? 그런 제네릭 함수?
