### 1\. 프론트엔드 개발의 흐름과 변화

#### 웹 개발 초기 \(서버 중심 시대\)

- <strong>방식:</strong> 서버 개발자\(Java 등\)가 웹 개발을 주도함\.
- <strong>기술:</strong> JSP와 같은 <strong>템플릿 엔진</strong>을 활용\.
- <strong>특징:</strong> 서버에서 고정된 HTML 틀에 변동 데이터를 채워 넣어 완성된 HTML을 클라이언트에 응답함\. 사실상 초창기 형태의 SSR 방식임\.
- <strong>한계:</strong> 사용자 인터랙션이 증가하면서 매번 페이지 전체를 새로고침해야 하는 성능적 한계 발생\.

#### AJAX의 등장과 레이어 분리

- <strong>정의:</strong> Asynchronous JavaScript and XML \(비동기 자바스크립트와 XML\)\.
- <strong>변화:</strong> 페이지 전체를 바꾸지 않고도 데이터만 비동기적으로 교환 가능해짐\.
- <strong>핵심:</strong> <strong>데이터 교환 레이어</strong>와 <strong>프레젠테이션\(UI\) 레이어</strong>를 분리함\. 화면 멈춤 없이 로딩 스피너 등을 통해 사용자 경험\(UX\)을 개선하기 시작함\.

### 2\. CSR의 시대와 한계점

#### CSR \(Client Side Rendering\)의 부상

- <strong>기술:</strong> React 등의 라이브러리/프레임워크 등장\.
- <strong>방식:</strong> 브라우저가 자바스크립트 파일을 받아 동적으로 HTML 태그를 생성하고 그림\.
- <strong>문제점:</strong>
   1. <strong>성능\(Performance\):</strong> 애플리케이션이 복잡해질수록 JS 번들 크기가 커짐 \-&gt; 다운로드 및 파싱 시간 증가 \-&gt; 사용자는 초기 화면에서 흰 화면\(White Screen\)만 보게 됨\.
   1. <strong>SEO \(Search Engine Optimization\):</strong> 초기 HTML에 내용이 없어 검색 엔진 봇이 정보를 수집하지 못함\.

### 3\. SSR의 재등장과 Next\.js 도입 배경

#### 프론트엔드 영역의 확장

- <strong>배경:</strong> CSR의 한계를 극복하기 위해 다시 서버에서 렌더링을 수행하는 SSR이 필요해짐\.
- <strong>새로운 과제:</strong> 이제 프론트엔드 개발자가 서버 운영, 인프라, 복잡한 서버 설정\(Configuration\)까지 담당해야 하는 상황이 됨\.
- <strong>Next\.js의 등장:</strong> 개발자가 비즈니스 로직과 UI 개발에만 집중할 수 있도록, 서버 설정 및 최적화 기능을 <strong>추상화\(Abstraction</strong>\)하여 제공하기 위해 탄생함\.

### 4\. 핵심 개념: 추상화와 자동 설정

#### 추상화 \(Abstraction\)

> 💡 <strong>&quot;복잡한 내부 로직\(번들링, 컴파일, 서버 설정\)을 감추고, 개발자가 손쉽게 사용할 수 있는 인터페이스만 노출하는 과정&quot;</strong>

- Next\.js는 라우팅, 데이터 패칭, 렌더링 최적화 등 복잡한 과정을 자동으로 처리함\.
- 개발자는 Next\.js가 제공하는 인터페이스만 사용하여 고성능 웹 애플리케이션을 구축할 수 있음\.

### 5\. Next\.js가 제공하는 주요 기능 \(Main Features\)

넥스트는 웹 애플리케이션이 갖추어야 할 기본 기능들을 프레임워크 차원에서 제공함\.

1. <strong>Routing:</strong> 파일 기반 시스템을 통한 손쉬운 경로 관리\.
1. <strong>Rendering:</strong> SSR, SSG, ISR 등 상황에 맞는 최적의 렌더링 방식 선택 가능\.
1. <strong>Data Fetching:</strong> 서버와 클라이언트 환경에 최적화된 데이터 가져오기 기능\.
1. <strong>Optimization:</strong> 이미지, 폰트 등 성능 향상을 위한 자동 최적화 도구 내장\.

### 6\. 요약 및 결론

- <strong>기술적 배경:</strong> 웹은 점차 고도화되었고, CSR의 성능 및 SEO 문제를 해결하기 위해 SSR이 필수적이 됨\.
- <strong>필요성:</strong> 프론트엔드가 관리해야 할 서버 환경의 복잡성을 Next\.js가 대신 처리해주기 때문에 도입함\.
- <strong>목표:</strong> Next\.js 사용 그 자체가 목적이 아니라, 이를 도구로 활용해 <strong>완성도 높은 웹 애플리케이션</strong>을 빠르고 효율적으로 만드는 것이 핵심임\.
