> 💡 **클래스가 참조 타입이고, 구조체가 값 타입인거 다 아는데 왜 공부하는거죠?
> 
> **해당 얘기와는 별개로 ARC를 통한 메모리 관리, 참조 타입과 값 타입에서의 각각의 특징에 따라 어느 때에 무엇을 쓰면 좋은지를 앎으로써 성능개선을 하는데 도움을 줍니다\.

## Class

- **Reference Type**
- ARC로 메모리를 관리합니다\.
- 같은 클래스 인스턴스를 여러개의 변수에 할당한 뒤 값을 변경하면 할당한 모든 변수에 영향을 줍니다
   → 참조 타입이니까 메모리만 복사 됩니다\.
- 상속이 가능합니다\.
- 타입 캐스팅을 통해 런타임에서 클래스 인스턴스의 타입을 확인할 수 있습니다\.
- deinit\(소멸자\)을 사용하여 클래스 인스턴스의 메모리 할당을 해제할 수 있습니다\.
   → 참조 타입이기 때문에 가능합니다\.

## Struct

- **Value Type**
- 구조체 변수를 새로운 변수에 할당할 때마다 새로운 구조체가 할당됩니다\.
   → 값 타입이니까 각 인스턴스의 값이 다릅니다\. 다른 변수에 영향을 주지 않습니다\.

## Class와 Struct의 공통점

- 프로퍼티, 메소드를 선언할 수 있습니다\.
- 내부 값에 \.을 선언해서 접근할 수 있습니다\.
- init\(\)을 사용하여 초기 상태를 설정할 수 있습니다\.
- Extension을 사용하여 기능을 확장할 수 있습니다\.
- Protocol을 채택하여 기능을 설정할 수 있습니다\.

## Class와 Struct의 차이점

```swift
class someClass {
    var cnt: Int = 0
    
    deinit {
        print("AClass deinit")
    }
}

struct someStruct {
    var cnt: Int = 0
}

var class1 = someClass()
var class2 = class1
var class3 = class1

class3.cnt = 3

print(class1.cnt) //class3의 값을 변경했지만 메모리만 복사될 뿐 참조 타입이기 때문에 값도 바뀝니다.

var struct1 = someStruct()
var struct2 = struct1
var struct3 = struct1

struct2.cnt = 2
struct3.cnt = 3

print(struct1.cnt) //0
print(struct2.cnt) //2
print(struct3.cnt) //3 구조체는 값 타입이기 때문에 항상 새로운 메모리가 할당됩니다.
```

## Class와 ARC, Retain Cycle

```swift
import Foundation

class SimpleClass {
    var count: Int = 0
    
    deinit {
        print("할당 해제")
    }
}

// ARC
print("ARC\n")
var classARC1: SimpleClass? = SimpleClass() // RC +1
print(CFGetRetainCount(classARC1)) // 2

var classARC2 = classARC1 // RC +1
print(CFGetRetainCount(classARC1)) //3

classARC1 = nil // RC -1
print(CFGetRetainCount(classARC2)) //2
classARC2 = nil // RC -1 
// RC = 1 deinit 실행
```

> 💡 **왜 RC의 기본값이 2인가요?
> 
> **RC의 경우 참조 타입을 변수에 할당하지 않고 생성 후 측정해보면 1입니다\. 즉, RC의 최소값은 0이 아니고 1입니다\. RC가 0이라는 것은 사실상 객체가 없다는 뜻이 됩니다\.
> 
> 
> 즉 참조 타입 객체는 RC가 1이 될 때 메모리에서 해제됩니다\. 이에 따라 RC를 측정하는 변수의 값이 nil이 될 때 RC가 1이 되므로 시스템에서 deinit을 호출하게 됩니다\.

## Stack 할당

스택은 LIFO\(Last In First Out\) 형태의 자료구조로 가장 마지막에 들어간 객체가 가장 먼저 나오게 되는 자료구조 입니다\. 자료구조의 특성상 하나의 명령어\(pop, push\)로 메모리를 할당, 해제할 수 있습니다\. 또한 컴파일 단계에서 언제 생성되고 해제되는지 알 수 있는 구조체와 같은 값들이 스택에 저장되게 됩니다\.

스레드들은 각각의 독립적인 스택 공간을 가지고 있기 때문에 스레드로부터 안전합니다\. 이러한 특징 때문에 스택의 값을 사용하는 것이 힙의 값을 사용하는 것보다 빠릅니다\.

## Heap 할당

힙에는 컴파일 단계에서 생성과 해제를 알 수 없는 참조 타입의 객체가 할당됩니다\. 힙은 메모리의 할당과 해제가 하나의 명령어로 처리되지 않습니다\. 참조 계산도 해줘야 하므로 스택보다 복잡합니다\.

힙은 스레드가 공유하는 메모리 공간이기 떄문에 스레드로부터 안전하지 않습니다\. 즉 이를 관리해주기 위한 lock과 같은 자원도 필요하게 되고 이는 곧 오버 헤드로 이어지게 됩니다\.

> 💡 **코딩 하다보면 클래스와 구조체를 혼합해서 쓰는 경우가 많다\.
> 예를 들어 클래스 안에 구조체가 있던가… 구조체 안에 클래스가 있던가…
> **
> **클래스\(참조 타입\) 안에 구조체\(값 타입\)가 있는 경우**
> \- 참조 타입이 할당 해제되기 전에 값 타입도 할당 해제되지 않기 위해 값 타입도 힙에 저장
> 
> 
> **구조체\(값 타입\) 안에 클래스\(참조 타입\)가 있는 경우
> **\- 값 타입은 힙에 할당되지 않지만 내부는 참조 타입이 있기 때문에 참조 카운트 처리해줘야 함** **

## Copy\-on\-assignment, Copy\-on\-write

### Copy\-on\-assignment

값 타입을 다른 변수에 할당하게 되면 복사를 하게 됩니다\. 즉 새로운 메모리 공간에 같은 값을 복사합니다\. 이를 Copy\-on\-assignment 라고 합니다\.

### Copy\-on\-write

다른 변수에 할당을 하면 일단은 메모리를 할당하지 않고 참조하고 있다가, 해당 값을 변경 할 때 실제로 메모리에 값을 복사하고 값을 변경하게 됩니다\. 이는 메모리를 최적화해주기 위함이며 이 작업을 Swift에선 Collection Type을 복사해서 사용할 때 일어납니다\.

## 언제 클래스, 언제 구조체?

- ` 단순한 값 `을 보유하기에는 구조체가 좋습니다\.
- 메모리의 스택은 크기가 크지 않기 때문에 ` 작은 값을 갖는 데이터를 처리 `할 때는 구조체를 사용합니다\.
- ` Objective-C와 상호 운용성 `을 원할 때는 클래스를 사용합니다\.
