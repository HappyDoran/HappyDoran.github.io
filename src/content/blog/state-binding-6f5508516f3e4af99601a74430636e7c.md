## @State

**SwiftUI로 관리되는 읽기/쓰기가 가능한 프로퍼티 래퍼 타입**

### @State Overview

App, Scene, View 등 뷰 계층구조 내에서 Single Source Of Truth\(SSOT\)로 값을 저장하기 위해서 기본값을 포함한 @State 속성을 적용한 프로퍼티를 사용하세요\.

> 💡 **SSOT란?**
> 
> 데이터베이스, 애플리케이션, 프로세스 등의 모든 데이터에 대해서 하나의 출처를 사용하는 개념
> 
> → 정확성, 일관성, 신뢰성을 보장하고, 일관성 있는 의사결정 및 작업 효율성을 높이는데 도움을 줍니다\.

SwiftUI에서 제공하는 스토리지 관리와 충돌할 수 있는 Memberwise Initializer에서 state를 설정하는 것을 방지하려면 private로 사용하길 권장합니다\.

```swift
struct PlayButton: View {
    @State private var isPlaying: Bool = false // state 생성

    var body: some View {
        Button(isPlaying ? "Pause" : "Play") { // state 읽기
            isPlaying.toggle() // state 쓰기
        }
    }
}
```

SwiftUI는 state로 선언된 프로퍼티들의 저장소를 관리합니다\.

값이 변경되면 swiftUI는 해당 프로퍼티 값이 표시되는 view 계층 부분의 일부를 자동으로 업데이트 해줍니다\.

→ **변화가 생기면 해당 변화를 자동으로 관찰하고 반영해주는 자동화 작업**을 의미

state로 선언된 프로퍼티들은 기본적으로는 wrappedValue\(상태 변수가 참조하는 기본 값, view를 표시하기 위한 데이터 값\)를 사용하여 선언 하지만, 프로퍼티를 직접 참조하면 Swift가 단축키 형태로 wrappedValue를 참조합니다\.

위의 예시에서는 state 프로퍼티인 isPlaying의 직접 참조를 하는 식으로 wrappedValue를 읽기/쓰기 하는 모습을 보여줍니다\.

state 프로퍼티는 현재 뷰의 UI의 특성을 저장하기 위해 만들어진 것이기 때문에 보통은 private로 선언합니다\.

하위뷰에서 읽기/쓰기를 사용하기 위해서는 @binding을 통해 공유해줍니다\.

클래스와 참조타입을 state 프로퍼티로 사용하고자 할때에는 @StateObject를 사용합니다\.\(@StateObject를 공부할때 다시한 번 공부\)

→ @Bindable을 쓰면 그럴 필요 없긴 합니다…

## 하위뷰와 State 공유 \- @Binding

```swift
struct PlayButton: View {
    @Binding var isPlaying: Bool // Play button now receives a binding.


    var body: some View {
        Button(isPlaying ? "Pause" : "Play") {
            isPlaying.toggle()
        }
    }
}
```

state 프로퍼티를 하위뷰로 전달하면 SwiftUI는 값이 변경될 때 마다 하위 뷰를 업데이트하지만, 하위뷰에서의 값을 수정할 수 없습니다\.

→ 하위뷰에서 수정을 하기위해서는 @Binding을 통해 전달하면 됩니다\.

state 프로퍼티에서 projectedValue\(binding 값을 반환\)를 통해 binding 값을 얻을 수 있으며, 이 값은 “$property명”형식으로 사용이 가능합니다\.

```swift
struct PlayerView: View {
    @State private var isPlaying: Bool = false // Create the state here now.


    var body: some View {
        VStack {
            PlayButton(isPlaying: $isPlaying) // Pass a binding.


            // ...
        }
    }
}
```

예를 들어 하위뷰 내의 button에서 binding 값을 적용하여 isPlaying 값을 false로 수정할 수 있습니다\.

상위 view에서 하위 view로 @Binding값으로 전달하기 위해서는 상위 view에서 state 프로퍼티로 선언을 해주고 $property 형식으로 전달해줍니다\.

state 프로퍼티는 항상 초깃값을 선언해준 후에 사용하세요\.

### Observable object 저장

@Observable 매크로를 사용하여 관찰이 가능한 개체를 생성할 수 있습니다\.

```swift
@Observable
class Library {
    var name = "My library of books"
    // ...
}


struct ContentView: View {
    @State private var library = Library()


    var body: some View {
        LibraryView(library: library)
    }
}
```

@State 프로퍼티는 항상 초깃값을 선언해줘야합니다\. 그래서 기본값을 초기화할 때 부작용과 성능집약적인 작업을 피해야 합니다\.

뷰가 자주 업데이트되는 경우 뷰가 초기화될 때마다 새 기본 개체를 할당하는 데 비용이 많이 드는 경우

→ task 모디파이어를 사용하여 개체의 생성을 연기할 수 있고, 뷰가 처음 랜더링될 때 한번만 호출

```swift
struct ContentView: View {
    @State private var library: Library?


    var body: some View {
        LibraryView(library: library)
            .task {
                library = Library()
            }
    }
}
```

이렇게 task를 통해 state 프로퍼티의 생성을 지연하면 불필요한 할당이 발생하지 않습니다\.

→ 네트워크 호출 또는 파일 액세스같은 다른 종류의 작업을 지연시키는 효과적인 방법입니다\.

### State object를 하위뷰와 공유

```swift
@Observable
class Book {
    var title = "A sample book"
    var isAvailable = true
}


struct ContentView: View {
    @State private var book = Book()


    var body: some View {
        BookView(book: book)
    }
}


struct BookView: View {
    var book: Book


    var body: some View {
        Text(book.title)
    }
}
```

state값이 저장된 상태에 저장된 Observable 개체를 하위뷰와 공유하려면 개체 참조를 하위뷰로 전달합니다\.

SwiftUI는 개체의 Observable속성이 변경될 때마다 하위뷰를 업데이트 하지만, 하위뷰의 본문에 변경되는 값이 포함 되있을 경우, 즉 본문이 해당 속성을 읽을 때만 업데이트 합니다\.

```swift
struct ContentView: View {
    @State private var book: Book?


    var body: some View {
        DeleteBookView(book: $book)
            .task {
                book = Book()
            }
    }
}


struct DeleteBookView: View {
    @Binding var book: Book?


    var body: some View {
        Button("Delete book") {
            book = nil
        }
    }
}
```

State 프로퍼티는 해당 값에 바인딩을 제공합니다\. 개체를 저장할 때, 특히 개체 참조가 일어날 때 해당 개체 상태에 저장된 참조를 변경할 때 유용합니다\.

```swift
struct ContentView: View {
    @State private var book = Book()


    var body: some View {
        BookCheckoutView(book: book)
    }
}


struct BookCheckoutView: View {
    var book: Book


    var body: some View {
        Button(book.isAvailable ? "Check out book" : "Return book") {
            book.isAvailable.toggle()
        }
    }
}
```

그러나 상태에 저장된 개체에 바인딩을 전달할 필요는 없습니다\. 예를 들어 참조에 바인딩 대신 개체 참조를 전달하여 하위 보기에서 개체의 속성을 새 값으로 설정할 수 있습니다

```swift
struct ContentView: View {
    @State private var book = Book()


    var body: some View {
        BookView(book: book)
    }
}


struct BookView: View {
    let book: Book


    var body: some View {
        BookEditorView(book: book)
    }
}


struct BookEditorView: View {
    @Bindable var book: Book


    var body: some View {
        TextField("Title", text: $book.title)
    }
}
```

개체의 특정 속성에 대한 바인딩이 필요한 경우에는 바인딩을 개체을 전달하고, 필요한 경우 특정 속성에 대한 바인딩을 추출하거나, 개체 참조를 전달하고 바인딩 가능 속성 래퍼인 @Bindable을 사용하여 특정 속성에 대한 바인딩을 생성합니다\.
