리액트에서 성능 최적화를 위해 여러 가지 방법을 사용할 수 있는데요\. 대표적으로 메모이제이션을 말씀 드릴 수 있겠습니다\.

리액트의 ` memo `를 사용하여 컴포넌트를 메모이제이션할 수 있습니다\.
이는 컴포넌트의 props가 변경되지 않았을 때, 리렌더링을 방지하여 성능을 최적화합니다\.
이는 특히 렌더링 비용이 큰 컴포넌트에서 유용합니다\.

또한 ` useCallback `과 ` useMemo `를 활용할 수도 있습니다\.
` useCallback ` 은 함수를 메모이제이션하여 불필요한 함수 재생성을 방지하고, ` useMemo `는 값의 재계산을 방지하여 성능을 최적화합니다\.
이를 통해 자식 컴포넌트로 전달되는 함수나 값이 변경되지 않으면 리렌더링을 피할 수 있습니다\.

마지막으로 ` 코드 스플리팅 `을 활용해볼 수 있습니다\.
코드 스플리팅은 큰 애플리케이션을 여러 개의 작은 청크로 나누어, 필요한 청크만 로드하게 하여 초기 로드 시간을 줄입니다\.
React\.lazy와 Suspense를 사용하여 동적으로 컴포넌트를 로드할 수 있습니다\.

### 코드 스플리팅은 어떤 경우에 사용해야 할까요? 🤔

첫번째로는 **초기 로딩 시간이 길어지는 경우**입니다\.
애플리케이션이 커지면, 초기 로딩에 모든 코드를 로드하는 것이 비효율적일 수 있습니다\. 코드 스플리팅을 사용해 초기 로드 시 필요한 핵심 코드만 로드하고, 이후 추가적인 기능은 필요할 때 로드하도록 하면 초기 로딩 속도를 크게 개선할 수 있습니다\.

두번째로는 **라우트별 코드 분할이 필요한 경우**입니다\.
SPA에서는 각 페이지가 별도의 기능과 UI를 가지므로, 라우트별로 필요한 코드만 분리하여 로드할 수 있습니다\. 이 방식은 리액트의 React\.lazy와 Suspense를 사용하여 라우트별 컴포넌트를 동적으로 불러올 때 유용합니다\.

## 면접 답변

#### 💡 \[버전 1\] 핵심만 찌르는 두괄식 답변 \(추천\)

> **&quot;리액트의 성능 최적화는 불필요한 리렌더링을 방지하는 &\#39;메모이제이션\(Memoization\)&\#39;과 초기 로딩 무거움을 해결하는 &\#39;코드 스플리팅\(Code Splitting\)&\#39;이 두 가지 큰 축을 이룹니다\.&quot;**

렌더링 비용을 줄이기 위해 상태 변화와 무관한 영역을 격리하고, 초기 번들 크기를 줄여 로딩 속도를 개선하는 방향으로 최적화를 진행합니다\.

- **메모이제이션 기법**:
   1. ` React.memo `: 이전 컴포넌트의 렌더링 결과를 재사용하여 props가 변하지 않았다면 리렌더링을 방지합니다\.
   1. ` useCallback `: 함수를 메모이제이션하여, 부모가 리렌더링될 때 하위 컴포넌트로 전달되는 함수 참조 값이 변하지 않도록 고정합니다\.
   1. ` useMemo `: 무거운 연산의 결괏값을 메모이제이션하여 동일한 입력값에 대해 재연산을 차단합니다\.
- **코드 스플리팅 기법**: 애플리케이션 번들 파일을 작은 청크\(Chunk\)로 쪼개는 기술로, ` React.lazy `와 ` Suspense `를 활용해 **초기 로딩 속도가 지연될 때** 혹은 **특정 라우트 페이지에 진입할 때만** 해당 코드를 동적으로 불러옵니다\.

#### 📝 \[버전 2\] 꼬리 질문을 방어하는 상세 답변

> **&quot;리액트 최적화의 핵심은 컴포넌트가 언제 리렌더링되는지 이해하고, CPU 자원을 쓰는 연산 최적화\(메모이제이션\)와 네트워크 자원을 쓰는 로딩 최적화\(코드 스플리팅\)를 상황에 맞게 저울질하는 것입니다\.&quot;**

면접관님께서 질문하신 각 기술의 구체적인 실무 적용 기준과 무분별한 사용 시의 사이드 이펙트까지 방어하여 답변드리겠습니다\.

- **메모이제이션의 트레이드 오프 방어**: ` React.memo `, ` useCallback `, ` useMemo `는 언뜻 보면 무조건 쓰는 게 좋아 보이지만, 메모이제이션 자체가 &\#39;이전 값과 현재 값을 비교하는 연산 비용&\#39;과 &\#39;기존 결과를 메모리에 보관하는 비용&\#39;을 동반합니다\. 따라서 단순한 UI 컴포넌트나 가벼운 연산에 남발하면 오히려 성능이 저하됩니다\. 저는 실무에서 **&quot;자식 컴포넌트가 **` React.memo `**로 감싸져 있고, 그 자식에게 참조 타입\(함수/객체\)을 props로 내려줄 때만&quot;** ` useCallback `과 ` useMemo `를 세트로 연동하여 확실한 리렌더링 차단 효과를 봅니다\.
- **코드 스플리팅의 아키텍처적 활용**: 어플리케이션의 규모가 커지면 단일 번들 파일\(main\.js\)의 용량이 비대해져 첫 화면이 뜨는 TTI\(Time to Interactive\) 지표가 극도로 악화됩니다\. 이를 해결하기 위해 사용자가 당장 보지 않는 &\#39;마이페이지&\#39;, &\#39;관리자 화면&\#39; 등은 **라우터 레벨에서 **` React.lazy `**로 분할**하여 청크 파일로 떨어뜨립니다\. 이렇게 하면 첫 진입 시 다운로드할 파일 크기가 획기적으로 줄어 사용자 이탈률을 낮출 수 있으며, 컴포넌트 로딩 중 발생하는 빈 화면은 ` Suspense `의 ` fallback ` UI\(스켈레톤 등\) 처리를 통해 매끄러운 UX를 제공하고 있습니다\.
