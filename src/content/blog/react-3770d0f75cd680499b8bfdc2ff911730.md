React 성능 최적화는 렌더링·계산 비용을 줄이는 작업과 초기 로딩에서 필요한 코드를 줄이는 작업으로 나눌 수 있다\. memo·useMemo·useCallback과 코드 스플리팅을 어떤 조건에서 선택할지 정리한다\.

### 메모이제이션의 대상

부모가 다시 렌더링될 때마다 함수·객체를 새로 만들면 자식에 전달되는 참조도 바뀔 수 있다\. 자식이 memo로 감싸져 있더라도 props 참조가 달라지면 기대한 재사용이 일어나지 않을 수 있다\.

useCallback과 useMemo를 적용할 때는 값이 어떤 props 경계를 통과하는지 확인한다\. 도구를 함께 사용했다는 이유만으로 리렌더링 차단 효과를 보장하지 않는다\.

### 비교·보관 비용과 트레이드오프

메모이제이션에는 이전 값과 비교하는 비용과 기존 결과를 보관하는 비용이 있다\. 가벼운 계산이나 단순 UI에 일괄 적용하면 이득이 작거나 비용이 더 커질 수 있다\.

따라서 계산·렌더링 비용, props가 바뀌는 빈도, 참조를 고정할 필요를 기준으로 판단한다\. 메모이제이션을 모든 컴포넌트에 적용하는 고정 규칙으로 만들지 않는다\.

### 코드 스플리팅

코드 스플리팅은 번들을 여러 청크로 나눠 필요한 시점에 로드하는 방식이다\. React\.lazy와 Suspense를 이용해 동적 컴포넌트 로딩과 대기 UI를 구성할 수 있다\.

초기 로딩에서 모든 화면 코드를 가져오는 부담이 크거나 라우트별로 사용 시점이 나뉠 때 검토한다\. 예를 들어 첫 화면에 필요하지 않은 계정·관리 화면을 별도 청크로 나누는 방식이다\.

Suspense fallback에는 로딩 중 표시할 UI를 제공한다\. 분할한 컴포넌트가 준비되기 전 빈 화면만 남지 않게 하기 위해서다\.

### 두 최적화 축의 구분

메모이제이션은 반복 렌더링·계산 비용을, 코드 스플리팅은 코드 다운로드·초기 로딩 비용을 주로 다룬다\. 두 문제가 다르므로 한 도구가 다른 문제까지 해결한다고 가정하지 않는다\.

### 정리

- 반복되는 비용과 props 참조 경계를 확인한다\.
- memo·useMemo·useCallback의 대상과 자체 비용을 구분한다\.
- 초기 번들 부담은 사용 시점별 코드 분할로 검토한다\.
- 동적 로딩에는 fallback UI를 함께 구성한다\.
