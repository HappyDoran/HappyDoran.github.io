## 클로저에서 값을 캡쳐한다는 것

```swift
func doSomething() {
    var message = "Hi i am doran!"
 
    //클로저 범위 시작
    
    var num = 10
    let closure = { print(num) }
 
    //클로저 범위 끝
    
    print(message)
}
```

클로저 내부에서 외부 변수인 num이라는 변수를 사용하고 있기 때문에 num의 값을 클로저 내부적으로 저장하고 있는데, 이를 “클로저에 의해 num의 값이 캡쳐 되었다”라고 표현합니다\.

### 클로저의 값 캡쳐 방식

> 💡 <strong>클로저는 값을 캡쳐할 때 값 타입, 참조 타입에 관계 없이 </strong><strong>Reference Capture</strong><strong>합니다\. \(강한 참조\)</strong>
> 
> num은 Int 타입의 구조체 형식이고, 이는 곧 값 타입이기 떄문에, 값을 복사해서 들고 저장해야하는 것이 일반적입니다\. 하지만 클로저는 ` 값/참조 타입에 상관없이 캡쳐하는 값들을 참조 `합니다\. 이를 ` Reference Capture `라고 합니다\.

```swift
func doSomething() {
    var num: Int = 0
    print("num check #1 = \(num)")
    
    let closure = {
        print("num check #3 = \(num)")
    }
    
    num = 20
    print("num check #2 = \(num)")
    closure() // 클로저는 호출될 때 초기화 됨
}
```

먼저 클로저는 num이라는 외부 변수를 클로저 내부에서 사용하기 때문에 num을 캡쳐합니다\.

근데 이때 Reference Capture 방식, 즉 num이라는 변수를 참조하는 방식으로 캡쳐합니다\.

![](<../../assets/blog/notion-902fe2ca5eaf42ae9399c38b9d4941c5/image-001.png>)

클로저 내부에서 사용하는 num 값 또한 변경됩니다\.

그렇다면 만약 Value Type으로 Capture를 하고 싶으면 어떻게 해야 할까요?

## 클로저의 캡쳐 리스트

```swift
let closure = {[num1, num2] in 
		...
}
```

클로저의 시작인 \{ 의 바로 옆에 \[\]를 이용해 캡쳐할 멤버를 나열합니다\. 이때 in 키워드도 꼭 함께 작성해야 합니다\.

### Value Type의 값을 복사해서 Capture 하기

Capture Lists를 이용하면 할 수 있습니다\. 

Value Type의 경우  ` Value Capture를 하고 싶은 변수를 리스트로 명시 `해주는 것을 말합니다\.

```swift
func doSomething() {
    var num: Int = 0
    print("num check #1 = \(num)")
    
    let closure = { [num] in
        print("num check #3 = \(num)")
    }
    
    num = 20
    print("num check #2 = \(num)")
    closure()
}

```

![](<../../assets/blog/notion-902fe2ca5eaf42ae9399c38b9d4941c5/image-002.png>)

다음과 같은 코드에서 closure를 실행하기 전에 외부 변수인 num을 20으로 수정했지만, closure 내부에서 사용하는 num에는 영향을 주지 않는 모습을 볼 수 있습니다\.

이 때 closure를 선언할 당시의 num 값을 Const Value Type으로 캡쳐, 즉 상수로 캡쳐합니다\.

![](<../../assets/blog/notion-902fe2ca5eaf42ae9399c38b9d4941c5/image-003.png>)

### Reference Type의 값을 복사해서 Capture 하기

```swift
class Human {
    var name: String = "Doran"
}
 
var human1: Human = .init()
 
let closure = { [human1] in
    print(human1.name)
}
 
human1.name = "Unknown"
closure()
```

참조 타입의 클래스의 값을 Capture Lists에 작성하면, Value Capture가 될까요?

![](<../../assets/blog/notion-902fe2ca5eaf42ae9399c38b9d4941c5/image-004.png>)

캡쳐 리스트를 작성한다고 해도, Reference Type은 Reference Capture를 합니다\. 그렇다면 Reference Type은 클로저 캡쳐 리스트를 작성할 필요가 없나요?

## 클로저와 ARC

ARC란 인스턴스의 Reference Count를 자동으로 계산하여 메모리를 관리하는 방법입니다\.

```swift
class Human {
    var name = ""
    lazy var getName: () -> String = {
        return self.name
    }
    
    init(name: String) {
        self.name = name
    }
 
    deinit {
        print("Human Deinit!")
    }
}
```

다음과 같이 내가 Human이란 클래스를 만들고, name을 얻을 수 있는 Lazy 프로퍼티를 클로저를 통해 초기화 해주었습니다\. 

> 💡 <strong>lazy는 왜 붙어요?</strong>
> 
> 해당 프로퍼티가 self로 자신의 인스턴스에 접근하고 있기 때문입니다\. 인스턴스의 초기화가 다 진행되어 self를 사용할 수 있게 된 이후에나 해당 프로퍼티를 초기화 시킬 수 있기 때문에 lazy로 선언해야 합니다\.

그리고 다음과 같이

```swift
var doran: Human? = .init(name: "Seo-Dongwon") // RC +1
print(doran!.getName())

doran = nil // RC -1

//그렇다면 RC = 0...?
```

doran이란 인스턴스를 만들고, 클로저로 작성되어 있는 getName이란 지연 저장 프로퍼티를 호출했습니다\. 그  이후에 인스턴스에 nil을 할당했습니다\. 이 경우에 인스턴스의 RC가 0이 되어 deinit이 호출될 것이라고 예상할 것입니다\. 그렇기 때문에 deinit 함수가 호출될 것이라고 예상하지만, 그렇게 돌아가지 않죠…

### 클로저의 강한 순환 참조

먼저 클로저는 참조 타입이기 떄문에, Heap에 살고 있습니다\. 

```swift
class Human {
    var name = ""
    lazy var getName: () -> String = {
        return self.name // RC +1
    }
    
    init(name: String) {
        self.name = name
    }
 
    deinit {
        print("Human Deinit!")
    }
}

var doran: Human? = .init(name: "Seo-Dongwon")
print(doran!.getName()) //RC +1
```

따라서, 생성한 human이란 인스턴스는`  getName을 호출하는 순간 getName이란 클로저가 Heap에 할당이 되기 때문에 이 클로저를 참조 `할 것입니다\. 

→ 지연 저장 프로퍼티이기 떄문에 인스턴스 생성 직후가 아닌`  호출되는 순간에 메모리에 올라갑니다. `

getName이란 클로저를 보면 self를 통해 Human이란 인스턴스의 프로퍼티에 접근하고 있습니다\. 클로저는 참조된 값을 캡쳐할 때 기본적으로 “strong”으로 캡쳐를 합니다\. 따라서, 이때 Human이란 인스턴스의 Reference Count가 증가해버립니다\.

Human 인스턴스는 클로저를 참조하고, 클로저는 Human 인스턴스의 프로퍼티를 참조하기 때문에 ` 서로가 서로를 참조 `하고 있는 것이죠\. 물론 둘 다 메모리에서 해제되지 않는 강한 순환 참조입니다\.

그렇다면 어떻게 해결할까요?

### 클로저에서의 강한 순환 참조 해결법

강한 순환 참조는 weak &amp; unowned에 우리가 Reference Type일 땐 필요 없다 느꼈던 캡쳐 리스트를 이용해야합니다\.

클로저가 프로퍼티에 접근할 때,

```swift
 lazy var getName: () -> String = {
        return self.name
    }
```

즉 self를 참조하면서 RC가 증가하는 문제가 발생했었습니다\.

따라서 self에 대한 참조를 Closure Capture Lists를 이용해, weak, unowned로 캡쳐를 해버리면 됩니다\.

```swift
class Human {
    lazy var getName: () -> String? = { [weak self] in
        return self?.name
    }
}

class Human {
    lazy var getName: () -> String = { [unowned self] in
        return self.name
    }
}
```

#### 그러면 unowned를 언제 쓰는거죠?

위와 같이 ` 클로저를 Lazy Initialization로 선언해서 강한 순환 참조가 일어난 경우 `에 인스턴스가 존재해야만 접근해서 초기화 시킬 수 있고, 그러면 이제 self값이 있다고 단정을 지을 수 있기 때문에, 이 경우에는 unowned를 사용하여 옵셔널 바인딩을 하지 않아도 되기 때문에 코드가 깔끔해집니다\.

## 이름이 있는 클로저에서의 값을 캡쳐하는 방식

클로저는 전역함수, 중첩함수, 익명함수 이 세가지를 모두 아우르는 말입니다\. 따라서 named closure일 때 값을 캡쳐하는 방식을 봐봅시다\.

### 전역 함수

일반적으로 ` func를 쓰고 작성하는 함수 `를 말하는데, 이 전역 함수는 주변에 어떠한 값도 캡쳐하지 않습니다\.

### 중첩 함수

```swift
func outer() {
    var num: Int = 0
    
    func inner() {
        print(num)
    }
}
```

캡쳐 합니다\. 

## 중첩 함수 &amp; @escaping과 메모리의 관계

클로저를 함수의 파라미터로서 받을 때 @escaping이란 키워드 없이 받는 클로저는 모두 non\-escaping 클로저이고 ` 함수 내부에서 직접 실행하기 위해서만 사용 `하고, ` 변수나 상수에 대입이 불가 `하며, ` 함수가 종료되기 전에 무조건 실행 `되어야 합니다\. 이러한 이유는 클로저가 함수 외부로 탈출하지 못하게 하기 위해서입니다\. 

```swift
var handler: (() -> Void)?

func 함수(closure: () -> Void) {
    handler = closure //Assigning non-escaping parameter 'closure' to an @escaping closure
}
```

위와 같이 함수 외부에 정의된 변수에 저장을 하려면, 에러가 발생합니다\.

기본적으로 클로저는 non\-escaping 클로저이기 때문에, 이를 외부 변수에 저장할 수 없습니다\. 따라서 외부 변수에 저장을 하려면 @escaping 키워드를 붙여야합니다\. 

```swift
var handler: (() -> Void)?

func 함수(closure: @escaping () -> Void) {
    handler = closure
}
```
